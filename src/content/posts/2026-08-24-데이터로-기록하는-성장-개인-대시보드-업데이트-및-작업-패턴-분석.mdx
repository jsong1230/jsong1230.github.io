# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장, 대시보드 업데이트

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어에게 있어 '측정할 수 없는 것은 개선할 수 없다'는 말은 일종의 격언과도 같습니다. 저는 단순히 코드를 짜는 것에 그치지 않고, 제가 어떤 리듬으로 작업하고 어디에 시간을 쏟고 있는지 시각화하는 것을 즐깁니다. 오늘은 제 개인 대시보드의 데이터를 업데이트하며, 최근의 작업 패턴을 돌아보는 시간을 가졌습니다.

### 오늘의 작업: 대시보드 데이터 동기화

오늘 진행한 작업은 간단해 보이지만 저에게는 중요한 의미가 있는 `chore: Update dashboard data` 작업이었습니다. `src/data/dashboard.json` 파일을 업데이트하여 최근 7일 및 30일간의 커밋 활동량과 최신 커밋 메시지를 반영했습니다.

```json
// 변경 전
"last_msg": "Auto-generate weekly book post",
"commits_30d": 69

// 변경 후
"last_msg": "Auto-generate weekly recap",
"commits_30d": 70
```

단순한 숫자 변경처럼 보이지만, 이 데이터 속에는 제가 최근 집중하고 있는 기술적 관심사와 루틴이 고스란히 녹아 있습니다.

### 데이터가 말해주는 인사이트

이번 업데이트에서 특히 흥미로웠던 점은 `claude-agent` 리포지토리의 활동량입니다. `commits_30d`가 297회에 달하는 것을 보며, 최근 AI 에이전트의 자율성과 워크플로우 자동화에 얼마나 깊게 몰입했는지 다시금 깨달았습니다. 

특히 `docs: night sweep all healthy, fn2 in backup window`와 같은 커밋 메시지들은 제가 단순한 기능 구현을 넘어, 시스템의 안정성과 백업 윈도우, 그리고 상태 체크(Health Check)라는 운영적 관점에서의 자동화를 고민하고 있음을 보여줍니다. 20년 넘게 엔지니어 생활을 해오며 느낀 점은, 결국 훌륭한 시스템은 '잘 돌아가는 코드'가 아니라 '문제가 생겼을 때 빠르게 알 수 있고 복구 가능한 구조'에서 온다는 것입니다.

### 기술적 결정과 생각

저는 이 대시보드를 수동으로 관리하지 않고, 특정 스크립트를 통해 자동 생성(Auto-generate)하도록 구성했습니다. 

1. **자동화의 가치**: 매번 수동으로 입력하는 것은 낭비입니다. `Auto-generate weekly recap`이라는 메시지처럼, 반복되는 리포팅 작업은 최대한 자동화하여 '생각하는 시간'을 확보하는 것이 CTO로서, 그리고 엔지니어로서 제가 지향하는 방향입니다.
2. **가시성의 힘**: `activity` 배열에 담긴 일별 커밋 수치들을 통해 제 컨디션과 집중도 사이의 상관관계를 분석합니다. 특정 요일에 활동량이 급증하거나 급감하는 패턴을 보며 업무 강도를 조절하는 지표로 삼고 있습니다.

### 마치며

씨피랩스에서 수많은 복잡한 아키텍처를 설계하고 Web3와 AI의 접점을 찾는 일도 중요하지만, 이렇게 개인의 기록을 정돈하는 시간은 저에게 일종의 '정신적 리팩토링'과 같습니다. 

코드 한 줄, 커밋 하나가 쌓여 데이터가 되고, 그 데이터가 다시 저의 성장 궤적을 그려냅니다. 여러분도 본인만의 '성장 대시보드'를 만들어보시는 건 어떨까요? 기록되지 않은 노력은 잊혀지기 쉽지만, 기록된 데이터는 반드시 성장의 밑거름이 됩니다.
