## [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어에게 있어 '기록'은 단순한 메모 이상의 의미를 갖습니다. 제가 작성하는 코드가 서비스의 기능을 결정한다면, 제가 남기는 기록은 제가 어떤 고민을 하며 성장해왔는지를 보여주는 '기술적 지문'과 같기 때문입니다.

오늘은 제 개인 대시보드의 데이터를 업데이트하는 간단한 작업(`chore: Update dashboard data`)을 진행했습니다. 겉으로 보기에는 단순한 JSON 파일의 수정처럼 보이지만, 이 데이터들이 담고 있는 의미와 이를 관리하는 방식에 대해 잠시 이야기를 나눠볼까 합니다.

### 1. 무엇을 해결하려 했는가?

저는 제가 관리하는 여러 프로젝트의 활동량(Commit 수, 최근 업데이트 날짜, 메시지 등)을 한눈에 볼 수 있는 개인 대시보드를 운영하고 있습니다. 매일 쏟아지는 수많은 태스크 속에서 내가 어디에 시간을 쏟고 있는지, 어떤 프로젝트가 현재 활발하게 진행되고 있는지를 시각화하여 '메타 인지'를 높이기 위함입니다.

오늘의 작업은 자동화된 스크립트를 통해 최신 레포지토리 상태를 `dashboard.json`에 반영하는 것이었습니다.

### 2. 코드 변경점과 기술적 인사이트

이번 diff에서 흥미로운 점은 단순히 숫자만 바뀐 것이 아니라, 관리하는 프로젝트의 구성이 변했다는 점입니다.

```json
- "name": "claude-agent",
- "commits_7d": 53,
- "commits_30d": 458
+ "name": "claude-agent",
+ "commits_7d": 40,
+ "commits_30d": 437
...
+ {
+   "name": "booksummary",
+   "last_date": "2026-11-12",
+   "last_msg": "feat: 「대온실 수리 보고서」(김금희) 제작·업로드",
+   ...
+ }
```

특히 `claude-agent` 프로젝트의 활동량 변화와 새롭게 정비된 `booksummary` 레포지토리의 진입이 눈에 띕니다. 여기서 제가 얻은 인사이트는 **'데이터의 정규화와 우선순위'**입니다. 

초기에는 모든 레포지토리를 무작위로 나열했지만, 시간이 흐를수록 '현재 집중하고 있는 도메인'과 '유지보수 단계의 도메인'이 명확히 구분됩니다. 이를 위해 데이터를 업데이트할 때 단순히 리스트를 추가하는 것이 아니라, 활동성(Activity) 지표를 기반으로 가중치를 두어 대시보드에 노출하는 구조로 개선하고 있습니다.

### 3. 마치며: 엔지니어의 '대시보드'란

20년 넘게 엔지니어로 살며 깨달은 점은, 복잡한 시스템일수록 **'가시성(Visibility)'**이 중요하다는 것입니다. 이는 거대한 분산 시스템의 모니터링 툴뿐만 아니라, 개인의 커리어 관리에도 동일하게 적용됩니다.

내가 어떤 기술적 결정(Decision)을 내렸고, 그것이 실제 커밋으로 어떻게 이어졌으며, 결과적으로 어떤 데이터로 남았는지를 추적하는 과정. 이것이 바로 제가 씨피랩스에서 팀을 리딩하고 기술적 방향성을 설정할 때 사용하는 '데이터 기반 사고'의 기초가 됩니다.

단순한 JSON 파일의 업데이트였지만, 다시 한번 저의 지난 일주일을 복기하며 다음 단계의 성장을 설계할 수 있었던 시간이었습니다. 여러분은 여러분의 성장을 어떻게 기록하고 계신가요?
