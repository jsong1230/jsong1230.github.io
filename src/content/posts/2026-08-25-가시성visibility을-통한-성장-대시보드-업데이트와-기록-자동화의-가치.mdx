# [DevLog] 데이터의 흐름으로 기록하는 나의 성장: 대시보드 업데이트와 자동화의 가치

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한입니다.

엔지니어로서 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '가시성(Visibility)'입니다. 시스템의 상태를 모니터링하는 것뿐만 아니라, 내가 어떤 방향으로 나아가고 있고 어디에 시간을 쏟고 있는지를 정량적으로 파악하는 것이 성장의 핵심이기 때문입니다.

오늘은 개인 프로젝트인 `jsong1230.github.io`의 대시보드 데이터를 업데이트했습니다. 단순한 JSON 파일 수정처럼 보일 수 있지만, 이 작업 뒤에는 '기록의 자동화'와 '회고의 루틴'이라는 고민이 담겨 있습니다.

### 🛠 오늘의 작업: 대시보드 데이터 동기화

오늘의 주요 변경 사항은 `src/data/dashboard.json` 파일의 갱신입니다. 제가 운영하는 여러 저장소의 최신 커밋 메시지와 활동량(Activity)을 업데이트하는 작업이었죠.

```json
// 변경된 부분 중 일부
{
  "name": "metadium-explorer-stack",
  "last_date": "2026-08-24",
  "last_msg": "ops(monitor): blockstat 따라잡기 모니터 cron 제거 (목적 달성)",
  "commits_7d": 1,
  "commits_30d": 11
},
{
  "name": "claude-agent",
  "last_date": "2026-08-24",
  "last_msg": "docs: night sweep all healthy, 151 past 51%, HF ~113K blocks out",
  "commits_7d": 23,
  "commits_30d": 304
}
```

### 💡 기술적 결정과 인사이트

**1. '목적 달성' 후의 제거 (Clean-up)**
위의 diff에서 흥미로운 점은 `metadium-explorer-stack` 저장소의 커밋 메시지입니다. `"blockstat 따라잡기 모니터 cron 제거 (목적 달성)"`라는 문구가 보입니다. 

많은 엔지니어가 기능을 '추가'하는 데 집중하지만, 시니어 엔지니어일수록 '제거'하는 것에 더 큰 가치를 둡니다. 불필요한 모니터링 툴이나 임시로 만들어둔 크론잡(Cron Job)은 시간이 지나면 기술 부채가 됩니다. 목적을 달성했다면 과감히 제거하여 시스템을 단순하게 유지하는 것이 운영 효율을 높이는 길입니다.

**2. 정량적 지표를 통한 메타 인지**
`claude-agent` 저장소의 30일 커밋 수가 304회에 달하는 것을 보며, 최근 제가 AI 에이전트와 LLM 워크플로우 최적화에 얼마나 몰입하고 있는지를 다시 한번 확인했습니다. 이렇게 데이터를 통해 나의 관심사 변화를 추적하면, 막연한 느낌이 아니라 실질적인 지표를 바탕으로 다음 학습 계획을 세울 수 있습니다.

**3. 자동화의 힘**
이 데이터들은 수동으로 입력하는 것이 아니라, 스크립트를 통해 자동으로 생성됩니다. `last_msg`가 `"Auto-generate daily posts"`로 변경된 것처럼, 반복적인 기록 작업은 자동화하고 저는 그 데이터를 '해석'하는 데 시간을 쓰기로 결정했습니다. 이것이 바로 Web3와 AI 시대의 엔지니어가 가져야 할 생산성 전략이라고 생각합니다.

### 마치며

단순한 JSON 업데이트였지만, 그 속에는 씨피랩스에서 추구하는 '효율적인 운영'과 개인적인 '성장 기록'의 철학이 담겨 있습니다. 여러분은 자신의 성장을 어떻게 기록하고 계신가요? 때로는 화려한 코드보다, 정직하게 쌓인 커밋 로그 한 줄이 더 큰 가르침을 주곤 합니다.

오늘도 기록하며 성장하는 하루가 되시길 바랍니다.
