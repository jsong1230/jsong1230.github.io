# [Insight] 데이터의 흐름으로 기록하는 개발자의 삶: 대시보드 자동화의 가치

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한(Jeffrey)입니다.

개발자에게 '기록'은 단순히 과거를 남기는 것이 아니라, 자신의 성장 궤적을 확인하고 다음 단계의 생산성을 설계하는 중요한 과정입니다. 저는 개인적으로 제가 관리하는 여러 프로젝트의 활동량을 시각화하여 보여주는 대시보드를 운영하고 있습니다. 

오늘 진행한 작업은 단순해 보이지만, 제가 추구하는 '자동화된 기록'의 철학이 담긴 `dashboard.json` 데이터 업데이트 작업이었습니다.

### 무엇을 해결하려 했는가?

많은 개발자가 매주 혹은 매달 '회고'를 합니다. 하지만 기억에 의존한 회고는 주관적이며 누락되는 부분이 많습니다. 저는 이를 해결하기 위해 제가 운영하는 여러 레포지토리의 커밋 횟수, 최근 메시지, 활동 추이(Activity)를 JSON 형태로 추출하여 대시보드에 반영하는 시스템을 구축했습니다.

오늘의 커밋은 그 자동화된 파이프라인의 결과물입니다. `generated_at` 시점이 `2026-10-31`에서 `2026-11-01`로 갱신되며, 지난 24시간 동안의 제 기술적 발자취가 데이터로 치환되었습니다.

### 코드 변경에서 보이는 인사이트

이번 diff에서 흥미로운 지점은 단순히 숫자가 올라간 것이 아니라, **'관심사의 이동'**이 데이터로 나타난다는 점입니다.

```json
{
  "name": "heritageradio",
  "last_msg": "[admin] chore(audit-notify): 원고 변경 감지 — 변화 없으면 보내지",
  "commits_7d": 5,
  "commits_30d": 35
},
{
  "name": "booksummary",
  "last_msg": "feat: 「데카메론」(조반니 보카치오) 제작·업로드",
  "commits_7d": 16,
  "commits_30d": 59
}
```

특히 `heritageradio` 프로젝트의 커밋 메시지를 보면 `audit-notify` 기능을 통해 "변화가 없으면 알림을 보내지 않는" 로직을 구현했습니다. 이는 엔지니어로서 제가 항상 고민하는 **'노이즈 제거(Noise Reduction)'**의 관점이 반영된 결과입니다. 불필요한 알림을 줄이는 것이 곧 시스템의 효율이자 사용자의 경험을 개선하는 길이기 때문입니다.

또한, `booksummary` 레포지토리에 「데카메론」 업로드 건이 추가된 것을 보며, 기술적인 작업 외에도 인문학적 소양을 쌓기 위한 루틴이 깨지지 않고 유지되고 있음을 수치로 확인했습니다.

### 기술적 결정과 배운 점

저는 이 대시보드 데이터를 관리할 때 복잡한 DB를 사용하지 않고 정적 JSON 파일을 활용해 GitHub Pages에 배포하는 방식을 택했습니다. 

1. **단순함의 미학**: 데이터 규모가 작을 때는 오버엔지니어링보다 정적 파일 기반의 GitOps 방식이 훨씬 빠르고 안정적입니다.
2. **불변성(Immutability)**: Git 히스토리에 데이터가 남으므로, 특정 시점의 내 활동량을 언제든 추적할 수 있습니다.

### 마치며

20년 넘게 엔지니어로 살아오며 느낀 점은, 결국 **"측정할 수 없는 것은 개선할 수 없다"**는 것입니다. 오늘 업데이트한 이 짧은 JSON 데이터들은 저에게 단순한 숫자가 아니라, 제가 어디에 시간을 쏟았고 어떤 고민을 했는지를 보여주는 거울과 같습니다.

씨피랩스에서도 이러한 데이터 기반의 의사결정과 자동화 문화를 팀 전체로 확산시켜, 모두가 자신의 성장을 가시적으로 확인하며 즐겁게 개발할 수 있는 환경을 만드는 데 집중하고 있습니다.

여러분은 자신의 성장을 어떻게 기록하고 계신가요?
