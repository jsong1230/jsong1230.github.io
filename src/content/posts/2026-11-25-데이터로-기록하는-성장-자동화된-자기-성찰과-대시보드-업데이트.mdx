# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적

안녕하세요, 송주한(Jeffrey Joo-Han Song)입니다.

20년 넘게 엔지니어로 살아오며 제가 가장 중요하게 생각하는 것 중 하나는 '기록'입니다. 단순히 무엇을 개발했느냐를 넘어, 내가 어떤 리듬으로 움직이고 어디에 몰입하고 있는지를 객관적인 데이터로 바라보는 과정은 CTO로서, 그리고 개발자로서 스스로를 튜닝하는 가장 좋은 방법이기 때문입니다.

오늘은 제 개인 대시보드의 데이터를 업데이트하는 간단한 작업을 진행했습니다. 겉보기에는 단순한 JSON 파일 수정처럼 보이지만, 그 이면에는 '자동화된 자기 성찰'이라는 기술적 의도가 담겨 있습니다.

### 단순한 업데이트, 그 이상의 의미

오늘의 변경 사항은 `src/data/dashboard.json` 파일의 데이터를 갱신하는 것이었습니다. 

```json
-  "generated_at": "2026-11-23T23:00:01.452Z",
+  "generated_at": "2026-11-24T23:00:01.350Z",
```

이 짧은 diff 한 줄은 제 대시보드가 매일 자동으로 제 깃허브 활동을 추적하고 있음을 보여줍니다. 특히 흥미로운 점은 각 리포지토리별 `activity` 배열의 변화입니다. 

예를 들어, `claude-agent` 리포지토리의 활동량을 보면 최근 7일간의 커밋 수가 39개에서 51개로 급증한 것을 볼 수 있습니다. 
- `commits_7d`: 39 $\rightarrow$ 51
- `commits_30d`: 349 $\rightarrow$ 363

이 숫자들이 말해주는 것은 명확합니다. 최근 제가 AI 에이전트 설계와 구현에 깊게 몰입하고 있다는 사실이죠. 반면 `validator`나 다른 인프라 관련 작업들은 안정기에 접어들어 활동량이 낮게 유지되고 있습니다. 

### 기술적 결정: 왜 자동화된 데이터 대시보드인가?

많은 개발자가 깃허브의 '잔디(Contribution Graph)'를 통해 성실함을 증명하곤 합니다. 하지만 저는 여기서 한 걸음 더 나아가, **'어떤 도메인에 내 에너지가 투입되고 있는가'**를 정량적으로 파악하고 싶었습니다.

이를 위해 저는 다음과 같은 구조를 선택했습니다.
1. **데이터의 분리**: UI 로직과 데이터를 완전히 분리하여 JSON 형태로 관리합니다.
2. **자동 생성 파이프라인**: 수동으로 기록하는 것이 아니라, 스크립트가 API를 통해 데이터를 수집하고 커밋하는 구조를 만들었습니다. (이번 커밋의 `last_msg: "Auto-generate daily posts"`가 그 증거입니다.)
3. **시각적 피드백**: 누적된 데이터를 통해 나의 학습 곡선과 업무 비중을 한눈에 파악합니다.

### 인사이트: 엔지니어의 '메타 인지'

씨피랩스에서 수많은 프로젝트를 리딩하며 느낀 점은, 최고의 성과는 '무작정 열심히 하는 것'이 아니라 '내가 지금 어디에 있는지 정확히 아는 것'에서 시작된다는 점입니다. 

코드 한 줄을 수정하는 작업조차 데이터로 남기고 이를 다시 복기하는 과정은, 일종의 **'엔지니어링 메타 인지'** 훈련과 같습니다. 내가 생각하는 나의 몰입도와 실제 커밋 로그가 보여주는 데이터 사이의 간극을 확인하며, 저는 다음 주의 우선순위를 조정하고 학습 방향을 설정합니다.

단순한 `chore` 커밋이었지만, 오늘도 저는 데이터를 통해 저 자신의 성장 궤적을 확인했습니다. 여러분은 여러분의 성장을 어떻게 기록하고 계신가요?
