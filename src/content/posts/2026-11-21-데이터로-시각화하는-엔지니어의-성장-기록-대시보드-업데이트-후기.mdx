# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적: 대시보드 업데이트

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어에게 있어 '기록'은 단순히 과거를 남기는 행위가 아니라, 현재의 나를 객관화하고 미래의 방향성을 설정하는 중요한 도구입니다. 저는 개인적으로 제가 관리하는 여러 프로젝트의 활동량을 시각화한 대시보드를 운영하고 있습니다. 오늘은 이 대시보드의 기반이 되는 `dashboard.json` 데이터를 업데이트하며 느낀 몇 가지 생각들을 공유해보려 합니다.

### 단순한 데이터 업데이트, 그 이상의 의미

오늘 진행한 작업은 겉보기에는 매우 단순한 `chore: Update dashboard data` 커밋입니다. 하지만 이 JSON 파일 하나에는 제가 최근 집중하고 있는 기술적 관심사와 시간의 배분이 고스란히 담겨 있습니다.

이번 변경 사항에서 흥미로운 점은 각 레포지토리의 `activity` 배열과 `commits_7d` 수치의 변화입니다. 특히 `claude-agent` 프로젝트의 활동량이 눈에 띕니다.

```json
{
  "name": "claude-agent",
  "last_date": "2026-11-20",
  "last_msg": "log: briefick 11/20 registered...",
  "commits_7d": 35,
  "commits_30d": 343
}
```

최근 AI 에이전트의 자율성과 로그 분석 효율화에 깊은 관심을 두고 작업을 이어가고 있는데, 30일 기준 343개의 커밋이라는 숫자가 이를 증명합니다. 블록체인과 Web3 전문가로서 AI를 어떻게 접목해 개발 생산성을 극대화할 것인가에 대한 고민이 실제 코드와 커밋으로 이어지고 있음을 확인할 수 있었습니다.

### 기술적 결정: 정적 데이터 기반의 대시보드

많은 분이 실시간 API를 통해 대시보드를 구현하시겠지만, 저는 의도적으로 `dashboard.json`이라는 정적 파일을 업데이트하는 방식을 택하고 있습니다. 여기에는 두 가지 이유가 있습니다.

1. **성능과 비용의 최적화**: 굳이 매번 API를 호출해 연산할 필요 없이, 빌드 타임에 결정된 데이터를 서빙함으로써 런타임 오버헤드를 제로로 만듭니다.
2. **Git을 통한 이력 관리**: 데이터의 변화 자체가 하나의 Git 히스토리가 됩니다. "내가 언제 어떤 프로젝트에 몰입했는가"를 `git diff`만으로도 추적할 수 있다는 점이 매우 매력적입니다.

### 인사이트: '측정할 수 없으면 개선할 수 없다'

피터 드러커의 말처럼, 측정되지 않는 성장은 막연한 느낌일 뿐입니다. 오늘 `booksummary` 프로젝트에 한강 작가의 「바람이 분다, 가라」 제작 내용을 업데이트하며, 기술적인 작업 외에도 인문학적 소양을 쌓는 루틴이 제 삶의 밸런스를 어떻게 유지해주고 있는지 수치로 확인했습니다.

씨피랩스에서 수많은 엔지니어를 리딩하며 제가 항상 강조하는 것은 **'가시성(Visibility)'**입니다. 그것이 시스템의 모니터링이든, 개인의 성장 기록이든, 현재 상태를 정확히 파악할 수 있는 지표가 있을 때 우리는 비로소 올바른 기술적 의사결정을 내릴 수 있습니다.

오늘의 작은 커밋 하나가 모여 저라는 엔지니어의 거대한 맵을 그려나가고 있다고 믿습니다. 여러분은 여러분의 성장을 어떻게 기록하고 계신가요?
