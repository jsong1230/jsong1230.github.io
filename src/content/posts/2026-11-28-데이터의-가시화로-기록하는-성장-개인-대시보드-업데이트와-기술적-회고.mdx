# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장: 대시보드 업데이트와 회고

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어로서 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 **'가시화(Visualization)'**입니다. 단순히 코드를 짜고 배포하는 것에 그치지 않고, 내가 어떤 리포지토리에서 어떤 고민을 했으며, 시간의 흐름에 따라 나의 관심사와 생산성이 어떻게 변하고 있는지를 데이터로 확인하는 과정은 매우 중요합니다.

오늘은 개인 대시보드(`jsong1230.github.io`)의 데이터를 업데이트하며, 최근의 작업 흐름을 되짚어보는 시간을 가졌습니다.

### 🛠 오늘의 작업: 대시보드 데이터 동기화

오늘 진행한 작업은 단순해 보이지만, 저에게는 일종의 '기술적 회고'와 같습니다. `src/data/dashboard.json` 파일을 업데이트하여 최근 7일 및 30일간의 커밋 활동과 최신 메시지를 반영했습니다.

```json
// 변경된 데이터의 일부
{
  "name": "validator",
  "last_date": "2026-11-27",
  "last_msg": "런북: v2.2.5 보류 추가(소장님)",
  "commits_7d": 2,
  "commits_30d": 4
},
{
  "name": "metadium-explorer-stack",
  "last_date": "2026-11-27",
  "last_msg": "feat(delegator): testnet develop-04d52ad 배포 스크립트...",
  "commits_7d": 2,
  "commits_30d": 19
}
```

### 💡 기술적 결정과 인사이트

이번 업데이트에서 흥미로운 점은 제가 관리하는 여러 프로젝트의 **'활동 밀도'**가 변하고 있다는 점입니다.

1. **운영 안정성으로의 무게중심 이동**: `validator` 리포지토리의 최신 메시지인 *"런북: v2.2.5 보류 추가"*에서 알 수 있듯, 최근의 관심사는 단순한 기능 구현보다는 장애 대응 매뉴얼(Runbook) 고도화와 같은 **운영의 안정성**에 맞춰져 있습니다. Web3 인프라를 다루는 씨피랩스의 엔지니어로서, 시스템의 가용성을 높이는 것은 그 어떤 화려한 기능보다 우선순위가 높기 때문입니다.

2. **에이전트 기반 자동화의 실험**: `claude-agent` 리포지토리의 활동량을 보면 한때 폭발적인 커밋이 있었습니다. AI 에이전트를 활용해 워크플로우를 자동화하려는 시도가 반영된 결과입니다. 비록 최근 활동 수치는 낮아졌지만, 이는 '개발 단계'에서 '최적화 및 안정화 단계'로 진입했음을 의미합니다.

3. **데이터 기반의 자기 객관화**: `activity` 배열(0, 0, 0, 1, 0, 1, 0 등)을 통해 일주일간의 리듬을 확인합니다. 특정 날짜에 집중된 커밋과 분산된 커밋을 비교하며, 제가 어떤 리듬으로 일할 때 가장 효율적인지, 혹은 어떤 부분에서 병목이 발생하는지를 정량적으로 파악할 수 있습니다.

### 🚀 마치며

많은 이들이 커밋 횟수(잔디 심기)에 집착하곤 합니다. 하지만 시니어 엔지니어에게 중요한 것은 '얼마나 많이 썼느냐'가 아니라 **'어떤 방향으로 움직이고 있느냐'**입니다.

오늘의 `dashboard.json` 업데이트는 단순한 `chore` 작업이 아니라, 제가 추구하는 기술적 지향점(AI 자동화 $\rightarrow$ 인프라 안정화 $\rightarrow$ Web3 생태계 확장)을 확인하는 과정이었습니다. 

앞으로도 씨피랩스에서 마주하는 수많은 기술적 도전들을 기록하고, 이를 통해 더 나은 아키텍처와 운영 체계를 만들어가겠습니다.
