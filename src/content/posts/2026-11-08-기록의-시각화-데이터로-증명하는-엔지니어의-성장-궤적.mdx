# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어에게 있어 '기록'은 단순히 과거를 남기는 것이 아니라, 자신의 성장 궤적을 데이터로 확인하는 과정이라고 생각합니다. 저는 평소 제가 진행하는 다양한 프로젝트들의 활동량을 시각화하여 대시보드로 관리하고 있습니다. 오늘 진행한 작업은 간단한 `dashboard.json` 데이터 업데이트였지만, 이 작은 변경 사항 속에 담긴 의미를 공유해보고자 합니다.

### 🛠 오늘의 작업: 대시보드 데이터 최신화

오늘의 주요 작업은 개인 대시보드에 반영될 최신 깃허브 활동 데이터를 업데이트하는 것이었습니다. 

```json
// src/data/dashboard.json 변경 부분
- "generated_at": "2026-11-06T23:00:01.082Z",
+ "generated_at": "2026-11-07T23:00:01.587Z",
```

단순히 날짜를 바꾸는 작업처럼 보이지만, 이 JSON 파일은 제가 운영하는 여러 저장소(Repo)의 커밋 횟수, 최근 메시지, 그리고 일주일간의 활동 추이를 담고 있습니다.

### 💡 기술적 인사이트: 정적 데이터의 동적 관리

저는 대시보드를 구축할 때 실시간 API 호출보다는 **'정적 데이터 생성(Static Data Generation)'** 방식을 선택했습니다. 매번 페이지를 로드할 때마다 깃허브 API를 호출하는 것은 레이턴시를 발생시킬 뿐만 아니라, API Rate Limit에 걸릴 위험이 있기 때문입니다.

대신, 특정 주기마다 데이터를 수집해 JSON 파일로 저장하고 이를 배포하는 방식을 사용합니다. 이번 커밋에서도 볼 수 있듯, `activity` 배열의 값들이 변하며 나의 최근 집중도가 어디에 쏠려 있는지를 보여줍니다.

특히 흥미로운 부분은 `booksummary` 저장소의 변경점입니다.
```json
- "last_msg": "feat: 「백의 그림자」(황정은) 제작·업로드",
+ "last_msg": "feat: 「인간의 굴레에서」(서머싯 몸) 제작·업로드",
```
기술적인 작업 외에도 독서 기록을 자동화하여 관리하는 루틴이 데이터로 치환되어 나타나는 지점입니다. 엔지니어로서의 기술적 성장과 인문학적 소양의 균형을 맞추려는 저의 노력이 이 한 줄의 `last_msg` 변경에 담겨 있습니다.

### 🚀 마치며: 데이터는 거짓말을 하지 않는다

`claude-agent` 저장소의 높은 커밋 수와 `heritageradio`의 안정적인 유지보수 기록을 보며, 현재 제가 어떤 기술적 챌린지에 몰입하고 있는지 객관적으로 파악할 수 있었습니다. 

씨피랩스에서 CTO로서 수많은 아키텍처 결정을 내리고 팀을 리딩하고 있지만, 개인적인 공간에서는 이렇게 작은 데이터 하나하나를 쌓아 올리는 '메이커(Maker)'의 마음가짐을 유지하려 노력합니다. 

결국 거대한 시스템의 안정성도 작은 커밋 하나, 데이터 한 줄의 정확성에서 시작된다는 점을 다시 한번 느낀 하루였습니다. 내일은 또 어떤 데이터가 나의 대시보드를 채우게 될지 기대됩니다.
