# [Dev Log] 데이터의 흐름으로 기록하는 성장: 대시보드 업데이트와 자동화의 가치

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어로 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '기록의 자동화'입니다. 매일 쏟아지는 수많은 코드 변경점과 기술적 의사결정을 일일이 수동으로 기록하는 것은 불가능에 가깝습니다. 그래서 저는 저만의 개인 대시보드를 통해 제가 어떤 프로젝트에 시간을 쏟고 있는지, 개발 활동의 리듬은 어떻게 변하고 있는지를 데이터로 추적하고 있습니다.

오늘 진행한 작업은 단순해 보이지만, 제 개발 루틴의 핵심인 `dashboard.json` 데이터를 업데이트하는 작업이었습니다.

### 오늘의 작업: 대시보드 데이터 동기화

오늘의 커밋 내역을 보면 `src/data/dashboard.json` 파일의 대대적인 수정이 있었습니다. 이는 단순한 텍스트 수정이 아니라, 최근 7일 및 30일간의 커밋 활동량(`activity`), 마지막 커밋 메시지(`last_msg`), 그리고 업데이트 날짜를 최신화하는 과정입니다.

```json
// 변경 전
"last_msg": "docs: STATUS.md 를 역사 기록으로 정리 (STATUS-2026-04-17.md 로 개명)",
"commits_7d": 46,

// 변경 후
"last_msg": "docs(deploy): sync 3대 #39·#40 배포 완료 (6251c329) + 정지확인 사고 ",
"commits_7d": 48,
```

### 기술적 인사이트: '메타 데이터'가 주는 관점의 전환

단순히 JSON 파일을 업데이트하는 것이 왜 의미가 있을까요? 저는 여기서 두 가지 인사이트를 얻습니다.

**첫째, 활동의 가시화(Visibility)입니다.**
`metadium-explorer-stack`이나 `claude-agent` 같은 프로젝트의 `activity` 배열을 보면, 특정 날짜에 작업량이 폭증했다가 다시 줄어드는 패턴이 보입니다. 이는 단순한 '열심히 했다'는 느낌을 넘어, 현재 제가 직면한 문제의 난이도나 프로젝트의 라이프사이클을 객관적으로 보여줍니다. 특히 `claude-agent` 프로젝트에서 나타나는 높은 커밋 빈도는 최근 AI 에이전트의 메모리 충돌 문제(`memory conflict markers`)를 해결하기 위해 얼마나 치열하게 고민했는지를 증명하는 지표가 됩니다.

**둘째, 자동화된 회고의 기반이 됩니다.**
`jsong1230.github.io` 리포지토리의 메시지가 `"Auto-generate weekly recap"`에서 `"Auto-generate daily posts"`로 변경된 점이 흥미롭습니다. 기록의 단위를 주간에서 일간으로 좁힘으로써, 더 세밀한 피드백 루프를 구축하려는 시도입니다. Web3나 AI 분야처럼 변화 속도가 빠른 도메인에서는 일주일의 공백조차 큽니다. 매일의 기록을 자동화하고 이를 대시보드화하는 것은, CTO로서 기술적 방향성을 잃지 않기 위한 저만의 '나침반'을 만드는 작업과 같습니다.

### 마치며

많은 개발자가 기능 구현과 버그 수정에 매몰되곤 합니다. 하지만 시니어 엔지니어, 더 나아가 CTO의 역할은 전체적인 흐름을 읽고 최적의 결정을 내리는 것입니다. 

오늘처럼 내 활동 데이터를 정량적으로 정리하는 습관은, 내가 어디에 과하게 에너지를 쓰고 있는지, 혹은 놓치고 있는 영역은 없는지를 판단하게 해줍니다. 결국 좋은 코드는 좋은 관리와 성찰에서 나오기 때문입니다.

내일은 오늘 업데이트한 이 데이터들이 또 어떤 새로운 인사이트를 줄지 기대됩니다.
