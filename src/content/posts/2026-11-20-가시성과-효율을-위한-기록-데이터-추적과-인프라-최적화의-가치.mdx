# [Dev Log] 데이터의 흐름을 기록하고, 인프라의 군더더기를 덜어내는 일

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어로서 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '가시성(Visibility)'입니다. 시스템이 어떻게 돌아가고 있는지, 내가 어디에 시간을 쓰고 있는지, 그리고 인프라에 불필요한 찌꺼기가 쌓여있지는 않은지를 명확히 파악하는 것이 결국 기술적 부채를 줄이는 가장 빠른 길이기 때문입니다.

오늘 진행한 작업들은 규모가 큰 아키텍처의 변경은 아니었지만, 바로 이 '가시성'과 '정리'라는 관점에서 매우 의미 있는 작업들이었습니다.

### 1. 대시보드 데이터 업데이트: 나의 생산성을 수치화하다

먼저 개인 대시보드(`jsong1230.github.io`)의 데이터를 업데이트했습니다. 저는 단순히 코드를 짜는 것에 그치지 않고, 제가 관리하는 여러 레포지토리의 활동량을 JSON 형태로 추적합니다.

이번 업데이트에서 흥미로운 점은 `validator`와 `metadium-explorer-stack` 같은 핵심 프로젝트들의 활동이 다시 활발해졌다는 점입니다. 특히 `validator` 레포지토리에서 **"공개 RPC 조회 성공 시 회복 판정"**과 같은 로직 수정이 반영된 것을 볼 수 있습니다.

```json
{
  "name": "validator",
  "last_msg": "chain-watch: 공개 RPC 조회 성공 시 회복 판정 — 회복 알림이 다",
  "branch": "master",
  "commits_7d": 1,
  "commits_30d": 4
}
```

데이터를 통해 내가 최근 어떤 도메인에 집중하고 있는지, 어떤 문제가 해결되었는지를 한눈에 파악하는 습관은 CTO로서 리소스를 효율적으로 배분하는 데 큰 도움을 줍니다.

### 2. 인프라 다이어트: 10GB의 불필요한 바이너리 제거

오늘 가장 '손맛'이 좋았던 작업은 `claude-agent`를 통한 테스트넷 인프라 정리였습니다. 8대의 노드에 흩어져 있던 67개의 오래된 `gmet` 바이너리들을 찾아내어 삭제했는데, 무려 **10.06GB**의 용량을 확보했습니다.

현장에서 오래 일하다 보면, "혹시 몰라서" 남겨둔 백업 파일이나 이전 빌드 버전들이 서버 구석구석에 쌓이기 마련입니다. 하지만 실행 파일이 변경되지 않았음에도 중복되어 쌓여있는 데이터는 관리 포인트만 늘릴 뿐입니다. 이번 작업을 통해 인프라를 다시 가볍게 만들 수 있었습니다.

### 3. 시간의 기록: Briefick을 통한 정밀한 리소스 트래킹

마지막으로 오늘의 업무 시간을 정밀하게 기록(Briefick 등록)했습니다. 3.5시간의 업무를 4개의 세부 항목(GMET 정리, 연구소 관리, Explorer 검증, 밸리데이터 버그 수정)으로 나누어 기록했습니다.

특히 이번 기록에서는 `SendMessage` 같은 명시적 알림 없이도, Git 커밋 로그(`explorer 9e73306`, `validator f211685` 등)를 통해 실제 작업 여부를 판정하는 방식을 적용했습니다. **"코드가 곧 증거"**라는 엔지니어링 원칙을 시간 관리에도 적용한 셈입니다.

### 마치며: 정리는 곧 성능이다

코드의 리팩토링뿐만 아니라, 서버의 디스크 공간을 정리하고, 나의 하루 일과를 데이터로 정리하는 것 모두 본질적으로는 같습니다. 불필요한 노이즈를 제거하고 핵심에 집중할 수 있는 환경을 만드는 것이죠.

씨피랩스에서도 이러한 '정리'의 문화가 기술적 탁월함으로 이어질 수 있도록, 앞으로도 작은 디테일부터 챙겨나가려 합니다.
