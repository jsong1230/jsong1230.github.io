# [Dev Log] 데이터의 흐름으로 기록하는 나의 개발 리듬

안녕하세요, 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어로 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '가시성(Visibility)'입니다. 시스템의 상태를 모니터링하는 것만큼이나, 나 자신의 성장 궤적과 작업 리듬을 데이터로 확인하는 것은 매우 중요합니다. 

오늘은 제가 개인적으로 운영 중인 대시보드의 데이터를 업데이트하며, 최근의 작업 흐름을 되짚어보는 시간을 가졌습니다. 단순한 `chore` 작업처럼 보일 수 있지만, 그 이면에는 제가 지향하는 '데이터 기반의 자기 관리' 철학이 담겨 있습니다.

### 무엇을 해결하려 했는가?

저는 제가 참여하고 있는 다양한 프로젝트들의 활동량(Commit 수, 최근 업데이트 날짜, 메시지 등)을 자동으로 수집해 시각화하는 대시보드를 운영하고 있습니다. 오늘 진행한 작업은 `src/data/dashboard.json` 파일을 업데이트하여 최신 상태를 반영하는 것이었습니다.

단순히 숫자를 바꾸는 것이 아니라, 최근 어떤 프로젝트에 내 에너지가 집중되었는지, 그리고 그 리듬이 건강한지를 확인하는 과정입니다.

### 코드 변경점에서 보이는 인사이트

이번 diff에서 흥미로운 점은 프로젝트들의 '활동 밀도' 변화입니다.

```json
{
  "name": "heritageradio",
  "last_msg": "[admin+main] docs(CHANGELOG): 청음 player 월요일 00:05 조기 갱신 cron...",
  "commits_7d": 4,
  "commits_30d": 91
},
{
  "name": "claude-agent",
  "last_msg": "logs: 2026-07-27 add — CP-Guard 100 result + MAC-08 fix proposal delivered...",
  "commits_7d": 7,
  "commits_30d": 29
}
```

특히 `claude-agent` 프로젝트의 로그를 보면, 단순히 코드를 짜는 것을 넘어 `CP-Guard` 결과 분석이나 `fix proposal` 전달과 같은 설계 및 리뷰 작업이 활발했음을 알 수 있습니다. 

씨피랩스에서 CTO로서 수많은 프로젝트를 리딩하다 보면, 때로는 코드 한 줄의 변경보다 **'정확한 제안서 하나'**나 **'치밀한 분석 로그'**가 프로젝트의 방향을 결정짓는 결정적인 역할을 한다는 것을 체감합니다. `commits_7d` 수치는 낮을지 몰라도, 그 한 번의 커밋에 담긴 밀도가 훨씬 높았던 시기였음을 데이터가 말해주고 있습니다.

### 기술적 결정과 배운 점

저는 이 대시보드 데이터를 정적 JSON 파일로 관리하고 있습니다. 실시간 DB를 쓸 수도 있겠지만, 개인의 히스토리 기록에는 Git의 버전 관리 시스템만큼 완벽한 도구가 없습니다. 

1. **불변성(Immutability)의 기록**: JSON 파일이 커밋될 때마다 나의 개발 이력이 스냅샷 형태로 남습니다.
2. **낮은 오버헤드**: 별도의 서버 없이 GitHub Pages를 통해 빠르게 시각화할 수 있습니다.
3. **자기 객관화**: `activity` 배열(최근 7일간의 일별 커밋 수)을 통해 내가 어느 요일에 집중하고, 어느 시점에 번아웃이 오는지 패턴을 읽을 수 있습니다.

### 마치며

많은 개발자가 '무엇을 만들었는가'에 집중하지만, 시니어 엔지니어라면 '어떻게 일하고 있는가'라는 메타 인지적 관점이 필요합니다. 오늘 업데이트한 짧은 JSON 데이터들은 저에게 "최근 AI 에이전트와 가드레일 설계에 집중했구나"라는 확신과, "이제는 다시 다른 프로젝트의 밸런스를 잡을 때가 되었구나"라는 신호를 줍니다.

기술적인 깊이만큼이나 중요한 것은 지속 가능한 리듬을 찾는 것입니다. 여러분도 자신만의 '성장 대시보드'를 만들어보시는 건 어떨까요?
