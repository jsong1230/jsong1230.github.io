# [DevLog] 데이터의 흐름으로 기록하는 나의 성장, 대시보드 업데이트

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어에게 있어 '기록'은 단순히 과거를 남기는 것이 아니라, 자신의 성장 궤적을 확인하고 병목 지점을 찾아내는 중요한 피드백 루프입니다. 저는 개인적으로 제가 관리하는 여러 레포지토리의 활동량을 수치화하여 시각화하는 대시보드를 운영하고 있습니다. 오늘은 이 대시보드의 데이터를 최신화하며 느낀 몇 가지 생각들을 공유해보려 합니다.

### 오늘의 작업: 데이터 동기화와 활동 분석

오늘 진행한 작업은 단순해 보이지만 의미 있는 `chore: Update dashboard data`였습니다. `src/data/dashboard.json` 파일을 업데이트하여 최근 일주일 및 한 달간의 커밋 수와 활동 지표를 갱신했습니다.

```json
// 변경 사항 중 일부
"name": "claude-agent",
"last_date": "2026-08-01",
"last_msg": "docs: resume note for the next session after 2026-08-01",
"commits_7d": 46,
"commits_30d": 71
```

특히 눈에 띄는 부분은 `claude-agent` 레포지토리의 활동성입니다. 최근 7일간 46개의 커밋이 발생하며 매우 가파른 상승 곡선을 그리고 있습니다. AI 에이전트 관련 실험과 문서화 작업이 집중적으로 이루어진 결과인데, 이를 수치로 확인하니 제가 현재 어떤 기술적 관심사에 몰입하고 있는지가 명확히 드러납니다.

### 기술적 결정: 정적 데이터 기반의 가벼운 대시보드

많은 분이 실시간 API 연동을 통한 대시보드를 생각하시겠지만, 저는 의도적으로 `json` 파일에 데이터를 저장하고 정적 사이트로 배포하는 방식을 택했습니다. 여기에는 몇 가지 이유가 있습니다.

1. **성능과 비용**: 매번 GitHub API를 호출하는 대신, 빌드 타임에 데이터를 확정 지음으로써 로딩 속도를 극대화하고 API Rate Limit 문제를 원천 차단합니다.
2. **버전 관리**: 데이터의 변화 자체가 git history에 남습니다. "내가 언제부터 이 프로젝트에 집중했는가"를 `git diff`만으로 확인할 수 있다는 점이 매력적입니다.
3. **단순함의 미학**: 복잡한 백엔드 인프라 없이도 충분히 목적을 달성할 수 있다면, 가장 단순한 구조가 가장 견고한 구조입니다.

### 인사이트: 숫자가 주는 객관적 성찰

이번 업데이트를 통해 `cplabs_homepage`나 `heritageradio` 같은 프로젝트들의 활동성이 상대적으로 낮아진 것을 확인했습니다. 이는 단순히 '방치'했다는 의미가 아니라, 현재 나의 리소스가 AI와 Web3, 그리고 씨피랩스의 핵심 기술 스택으로 이동하고 있음을 보여주는 객관적인 지표가 됩니다.

엔지니어는 때로 자신의 직관보다 데이터에 기반해 우선순위를 재조정해야 합니다. 대시보드의 숫자가 낮아진 프로젝트가 있다면, 그것이 이제 유지보수 단계에 접어든 것인지, 아니면 다시 동력을 불어넣어야 할 시점인지를 판단하는 근거로 삼습니다.

### 마치며

코드 한 줄을 수정하는 것만큼이나, 내가 쓴 코드들의 흐름을 조망하는 시간은 중요합니다. 20년 넘게 엔지니어의 길을 걸어오며 배운 점은, 결국 **'측정할 수 없으면 개선할 수 없다'**는 것입니다.

여러분도 자신만의 '성장 지표'를 기록하고 계신가요? 거창한 툴이 아니더라도 좋습니다. 작은 기록들이 모여 여러분의 커리어를 증명하는 강력한 포트폴리오가 될 것입니다.

오늘도 기록하며 성장하는 하루 되시길 바랍니다.
