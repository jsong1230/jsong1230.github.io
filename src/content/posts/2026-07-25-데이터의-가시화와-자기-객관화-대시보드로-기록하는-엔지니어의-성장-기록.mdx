## [Dev Log] 데이터의 흐름으로 기록하는 나의 성장, 대시보드 업데이트의 의미

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어로서 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '가시화(Visualization)'입니다. 복잡한 블록체인 아키텍처나 Web3의 DID 생태계를 설계할 때도 결국 핵심은 "현재 상태가 어떠하며, 어디로 흘러가고 있는가"를 명확히 정의하는 것이기 때문입니다.

이러한 철학은 제 개인적인 작업 습관에도 적용됩니다. 저는 제가 어떤 프로젝트에 시간을 쏟고 있는지, 기술적 관심사가 어떻게 이동하고 있는지를 추적하기 위해 개인 대시보드를 운영하고 있습니다. 오늘 진행한 작업은 단순해 보이지만, 저에게는 매우 중요한 '자기 객관화' 과정인 `dashboard.json` 데이터 업데이트였습니다.

### 단순한 업데이트, 그 이상의 인사이트

오늘의 커밋 내역을 보면 `chore: Update dashboard data`라는 짧은 메시지와 함께 JSON 파일의 수정 사항이 보입니다. 겉으로 보기에는 날짜와 커밋 횟수 같은 숫자들의 변경이지만, diff를 자세히 살펴보면 흥미로운 지점들이 있습니다.

```json
-  "generated_at": "2026-07-23T23:00:01.587Z",
+  "generated_at": "2026-07-24T23:00:01.799Z",
```

매일 자동으로 생성되는 이 데이터는 제가 현재 집중하고 있는 '컨텍스트'를 보여줍니다. 이번 업데이트에서 특히 눈에 띄는 부분은 `jsong1230.github.io` 레포지토리의 활동성입니다.

```json
+        {
+          "name": "jsong1230.github.io",
+          "last_date": "2026-07-24",
+          "last_msg": "Auto-generate daily posts",
+          "activity": [3, 3, 2, 2, 2, 2, 0],
+          "commits_7d": 17,
+          "commits_30d": 69
+        },
```

최근 7일간 17번의 커밋, 30일간 69번의 커밋이 기록되었습니다. 단순히 코드를 많이 짰다는 의미가 아니라, 제가 지향하는 '지식의 기록과 공유'라는 루틴이 시스템적으로 잘 작동하고 있음을 확인하는 지표가 됩니다. 

### 기술적 결정: 자동화와 데이터 기반의 회고

저는 이 대시보드 데이터를 수동으로 입력하지 않습니다. API를 통해 내 활동 데이터를 수집하고 이를 JSON 형태로 자동 생성하여 정적 페이지에 반영하는 파이프라인을 구축해 두었습니다. 

여기서 제가 내린 기술적 결정의 핵심은 **"최소한의 비용으로 최대의 피드백 루프를 만드는 것"**이었습니다. 화려한 DB나 복잡한 백엔드 없이, 단순한 JSON 파일 하나를 Git으로 관리함으로써 버전 관리와 배포를 동시에 해결했습니다. 이는 씨피랩스에서 대규모 시스템을 설계할 때 항상 고민하는 '오버엔지니어링 경계하기'와 궤를 같이 합니다.

### 마치며: 기록하는 엔지니어의 힘

많은 분이 저에게 20년 넘게 기술적 열정을 유지하는 비결을 묻곤 합니다. 제 대답은 늘 같습니다. **"기록하고, 그것을 다시 바라보는 시간을 갖는 것"**입니다.

오늘 업데이트한 `dashboard.json`의 숫자들은 단순한 로그가 아닙니다. 제가 어떤 고민을 했고, 어떤 시행착오를 겪었으며, 어떻게 성장했는지를 보여주는 '기술적 발자취'입니다. 

여러분도 본인만의 '성장 대시보드'를 만들어보시는 건 어떨까요? 거창한 도구가 아니어도 좋습니다. 매일의 작은 기록이 모여 결국 대체 불가능한 전문가의 커리어를 만든다고 믿습니다.
