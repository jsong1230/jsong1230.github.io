# [Dev Log] 데이터의 흐름으로 기록하는 성장: 대시보드 자동화와 엔지니어의 관점

안녕하세요, 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어에게 '기록'은 단순히 과거를 남기는 일이 아니라, 현재의 생산성을 측정하고 미래의 방향성을 결정하는 중요한 데이터 포인트가 됩니다. 저는 평소 제가 관리하는 여러 레포지토리의 활동량을 시각화하여 개인적인 대시보드로 관리하고 있습니다. 오늘은 이 대시보드의 데이터를 업데이트하며 느낀 몇 가지 기술적 인사이트를 공유해보려 합니다.

### 1. 단순한 업데이트, 그 이상의 의미

오늘 진행한 작업은 표면적으로는 `src/data/dashboard.json` 파일의 데이터를 갱신하는 단순한 `chore` 작업이었습니다. 하지만 이 JSON 파일이 담고 있는 내용은 제가 최근 어떤 기술적 고민에 집중하고 있는지를 그대로 보여줍니다.

```json
// claude-agent 레포지토리의 활동 변화
"activity": [
  0, 0, 0, 0, 3, 9, 0
],
"commits_7d": 12,
"commits_30d": 38
```

위의 diff 내용을 보시면 `claude-agent` 레포지토리의 최근 7일간 커밋 수가 7개에서 12개로 급증했고, 특히 특정 일자에 활동량이 9회까지 튀어 오른 것을 볼 수 있습니다. 이는 최근 제가 AI 에이전트의 자율성과 LLM 오케스트레이션 최적화에 깊게 몰입하고 있음을 수치로 증명합니다. 

또한 `metadium-explorer-stack`과 같은 인프라 관련 레포지토리가 새롭게 추가된 점은, 최근 씨피랩스에서 진행 중인 테스트넷 익스플로러 파일럿 및 노드 동기화 최적화 작업과 궤를 같이합니다.

### 2. 기술적 결정: 정적 데이터 기반의 대시보드

많은 분이 이런 대시보드를 만들 때 실시간 API 호출 방식을 고민합니다. 하지만 저는 의도적으로 **정적 JSON 파일 기반의 생성 방식**을 택했습니다.

*   **성능 최적화:** 런타임에 GitHub API를 호출하면 Rate Limit 문제와 페이지 로딩 속도 저하가 발생합니다. 빌드 타임에 데이터를 생성해 정적 파일로 서빙하면 사용자(혹은 나 자신)는 즉각적인 응답 속도를 경험할 수 있습니다.
*   **이력 관리:** Git 커밋 로그 자체에 내 활동 데이터가 남기 때문에, 시간이 흐른 뒤 특정 시점에 내가 어떤 프로젝트에 집중했는지 `git diff`만으로도 쉽게 추적할 수 있습니다.

### 3. 엔지니어로서의 인사이트: "측정할 수 없다면 개선할 수 없다"

피터 드러커의 유명한 말처럼, 엔지니어링 역시 측정에서 시작됩니다. 단순히 "요즘 AI 공부를 많이 하고 있다"라고 느끼는 것과, 대시보드 상의 `commits_7d` 수치가 상승하는 것을 시각적으로 확인하는 것은 완전히 다른 경험입니다.

이번 업데이트를 통해 제가 깨달은 점은 **'데이터의 시각화가 주는 피드백 루프'**의 힘입니다. 내 활동 궤적을 객관적인 수치로 마주할 때, 비로소 내가 계획한 로드맵대로 움직이고 있는지, 혹은 특정 부분에 과하게 매몰되어 균형을 잃지는 않았는지 판단할 수 있기 때문입니다.

### 마치며

20년 넘게 개발자로 살며 수많은 도구와 프레임워크를 접했지만, 결국 가장 강력한 도구는 '나 자신을 객관화해서 볼 수 있는 시스템'이라는 생각이 듭니다. 씨피랩스에서의 도전적인 과제들과 개인적인 기술 탐구가 이 대시보드 위에서 어떻게 그려질지 기대됩니다.

여러분은 자신의 성장을 어떻게 기록하고 측정하고 계신가요? 단순한 메모를 넘어, 여러분만의 '데이터 대시보드'를 만들어 보시길 추천합니다.
