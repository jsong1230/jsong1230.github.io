# [Insight] 데이터의 흐름으로 기록하는 개발자의 성장 궤적

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한입니다.

개발자에게 '기록'은 단순히 기억을 보조하는 수단이 아닙니다. 내가 어떤 고민을 했고, 어떤 기술적 결정(Technical Decision)을 내렸으며, 시간이 흐름에 따라 나의 관심사가 어떻게 이동했는지를 보여주는 일종의 '성장 지도'와 같습니다.

오늘은 제 개인 대시보드의 데이터를 업데이트하며, 제가 왜 이러한 자동화된 기록 시스템을 유지하는지, 그리고 오늘 변경된 데이터가 시사하는 바가 무엇인지 공유해보려 합니다.

### 1. 오늘의 작업: 대시보드 데이터 동기화

오늘 진행한 작업은 단순해 보이지만 제게는 매우 중요한 루틴인 `dashboard.json` 업데이트였습니다. 제 개인 깃허브 페이지(`jsong1230.github.io`)에서 운영 중인 대시보드는 제가 관리하는 여러 저장소의 활동량과 최신 커밋 메시지를 자동으로 수집해 보여줍니다.

```json
// 변경 전
"last_msg": "Auto-generate weekly book post",
"commits_30d": 70

// 변경 후
"last_msg": "Auto-generate weekly recap",
"commits_30d": 71
```

단순히 숫자 하나가 올라간 것이 아니라, 지난 한 주간의 학습과 개발 결과물이 'Weekly Recap'이라는 형태로 응축되어 반영된 결과입니다.

### 2. 기술적 결정: '정적 데이터'와 '자동화'의 조화

저는 실시간 API 호출로 대시보드를 구성하는 대신, 주기적으로 JSON 파일을 생성해 푸시하는 방식을 택했습니다. 여기에는 두 가지 기술적 이유가 있습니다.

첫째, **성능과 비용의 최적화**입니다. 매번 방문자가 올 때마다 GitHub API를 호출하면 Rate Limit에 걸릴 위험이 있고, 페이지 로딩 속도가 느려집니다. 정적 JSON 파일을 사용하면 GitHub Pages의 CDN을 통해 즉각적인 응답 속도를 보장할 수 있습니다.

둘째, **데이터의 스냅샷화**입니다. `generated_at` 필드를 통해 특정 시점의 내 상태를 기록함으로써, 시간이 지난 뒤에 "내가 2026년 8월에는 어떤 프로젝트에 가장 몰입했는가?"를 추적할 수 있는 시계열 데이터를 확보할 수 있습니다.

### 3. 코드 변경에서 얻은 인사이트: 몰입의 지표

이번 diff에서 가장 흥미로운 부분은 `claude-agent` 저장소의 활동량 변화입니다.

```json
"commits_7d": 170  ->  177
"commits_30d": 236 ->  245
```

최근 AI 에이전트와 LLM 기반의 워크플로우 최적화에 깊게 몰입하고 있는데, 커밋 수와 활동량(`activity` 배열)의 수치가 이를 증명하고 있습니다. 특히 최신 메시지에서 `terminate old testnet server`와 같은 인프라 정리 작업이 포함된 것을 보며, 개발의 사이클이 '구축'에서 '최적화 및 정리' 단계로 넘어가고 있음을 체감합니다. 

엔지니어로서 가장 위험한 상태는 '정체'되는 것입니다. 저는 이렇게 숫자로 시각화된 내 활동량을 보며 스스로를 자극하고, 균형을 잡습니다. 특정 프로젝트에 과하게 쏠려 있다면 다른 기본기 학습(예: 이번 주 Book Post)으로 무게 중심을 옮기는 식이죠.

### 마치며

20년 넘게 엔지니어로 살아오며 느낀 점은, 결국 **"측정할 수 없는 것은 개선할 수 없다"**는 것입니다. 코드 한 줄의 효율성을 측정하듯, 내 삶과 커리어의 궤적 또한 데이터로 측정하고 기록하려 노력합니다.

씨피랩스에서도 이러한 데이터 기반의 의사결정 문화를 팀 전체로 확산시켜, 모두가 자신의 성장을 가시적으로 확인하며 즐겁게 개발할 수 있는 환경을 만드는 것이 저의 목표입니다.
