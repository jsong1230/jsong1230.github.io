# [DevLog] 데이터의 흐름으로 기록하는 나의 성장: 대시보드 자동화의 가치

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어로 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 **'측정 가능한 기록'**입니다. 단순히 "열심히 개발했다"는 느낌보다, 어떤 저장소에서 어떤 활동이 일어났고, 내 리소스가 어디에 집중되었는지를 데이터로 확인하는 과정은 메타인지를 높이는 데 매우 효과적이기 때문입니다.

오늘은 제 개인 대시보드(`jsong1230.github.io`)의 데이터를 업데이트하는 작업을 진행했습니다. 겉보기에는 단순한 JSON 파일 수정처럼 보이지만, 이 작업 뒤에는 '자동화된 기록'이라는 철학이 담겨 있습니다.

### 🛠 오늘의 작업: 대시보드 데이터 동기화

오늘의 커밋은 `chore: Update dashboard data`라는 간단한 메시지로 요약됩니다. 하지만 `diff`를 통해 살펴본 변화는 꽤 흥미롭습니다.

```json
// src/data/dashboard.json 변경 부분
- "generated_at": "2026-08-14T23:00:01.689Z",
+ "generated_at": "2026-08-15T23:00:02.037Z",
```

단순한 날짜 업데이트처럼 보이지만, 이는 제 개발 환경에서 돌아가는 자동화 스크립트가 각 레포지토리의 커밋 로그를 분석해 `activity` 배열과 `commits_7d`, `commits_30d` 같은 지표를 산출해낸 결과물입니다.

특히 눈에 띄는 부분은 `claude-agent`와 `business` 레포지토리의 활동량 변화입니다.
- `claude-agent`의 경우 30일 기준 커밋 수가 280개에서 284개로 늘어났고,
- `business` 레포지토리는 최근 7일간의 커밋이 8개에서 12개로 증가했습니다.

### 💡 기술적 결정과 인사이트: 왜 '데이터화' 하는가?

많은 개발자가 Git 커밋 로그 자체가 기록이라고 생각합니다. 하지만 수십 개의 레포지토리를 운영하다 보면, 전체적인 맥락(Context)을 한눈에 파악하기 어렵습니다. 저는 이를 해결하기 위해 **'데이터의 추상화'** 단계를 하나 더 두기로 결정했습니다.

1. **원천 데이터(Git Log) $\rightarrow$ 정제 데이터(JSON) $\rightarrow$ 시각화(Dashboard)**
2. 이 과정을 통해 저는 매일 "내가 어디에 시간을 쓰고 있는가?"를 객관적으로 바라봅니다. 
3. 예를 들어, 이번 업데이트에서 `booksummary`나 `jsong1230.github.io` 같은 개인 프로젝트의 활동이 꾸준히 유지되고 있음을 확인하며, 업무와 자기계발 사이의 균형을 체크합니다.

### 🚀 마치며

씨피랩스에서 CTO로서 복잡한 블록체인 인프라와 AI 에이전트 설계를 리딩하다 보면, 때로는 아주 작은 단위의 기록들이 모여 거대한 시스템의 방향성을 결정한다는 것을 깨닫습니다. 

오늘의 JSON 업데이트는 단순한 `chore` 작업이었지만, 저에게는 내일의 더 나은 설계를 위한 '이정표'를 세우는 작업이었습니다. 여러분도 본인만의 '성장 대시보드'를 만들어보시는 건 어떨까요? 

기록되지 않는 성장은 잊혀지지만, 데이터로 남은 성장은 자산이 됩니다.
