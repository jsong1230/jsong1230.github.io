# [Dev Log] 데이터의 흐름으로 기록하는 성장: 대시보드 자동화의 가치

안녕하세요, 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어로 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '측정 가능한 성장'입니다. 단순히 "열심히 했다"는 느낌보다, 실제 어떤 데이터가 어떻게 움직였는지를 시각화했을 때 비로소 개선점이 보이기 때문입니다.

오늘은 개인 대시보드의 데이터를 업데이트하며, 제가 구축해둔 자동화 파이프라인이 어떻게 작동하고 있는지 점검하는 시간을 가졌습니다.

### 🛠 오늘의 작업: 대시보드 데이터 갱신

오늘 진행한 작업은 단순해 보이지만, 제 개발 루틴의 핵심인 `dashboard.json` 파일을 업데이트하는 것이었습니다. 이 파일은 제가 관리하는 여러 레포지토리의 활동량, 커밋 횟수, 최근 메시지 등을 추적하여 시각화하는 데이터 소스로 활용됩니다.

**주요 변경 사항 (Diff 분석):**
```json
- "generated_at": "2026-11-14T23:00:01.560Z",
+ "generated_at": "2026-11-15T23:00:01.224Z",
...
- "commits_7d": 10,
- "commits_30d": 51
+ "commits_7d": 16,
+ "commits_30d": 69
```

단순한 숫자 변경처럼 보이지만, 여기서 흥미로운 점은 `jsong1230.github.io` 레포지토리의 활동성이 급증했다는 점입니다. 최근 주간 리캡(Weekly Recap) 자동 생성 기능을 강화하면서 `commits_7d` 수치가 10에서 16으로 상승한 것을 확인할 수 있습니다.

### 💡 기술적 결정과 인사이트: 왜 '자동화된 기록'인가?

저는 씨피랩스에서 CTO로서 수많은 복잡한 시스템을 설계하고 운영해왔습니다. 대규모 시스템일수록 모니터링과 대시보드의 중요성은 절대적입니다. 저는 이 철학을 개인의 성장 관리에도 적용했습니다.

**1. 데이터 기반의 자기 객관화**
`activity` 배열에 기록된 일별 커밋 수(예: `[2, 2, 2, 3, 3, 0]`)를 보면, 제가 어느 요일에 집중했고 어느 시점에 휴식을 취했는지 한눈에 보입니다. 이는 단순한 성실함의 척도가 아니라, 나의 에너지 사이클을 파악하는 도구가 됩니다.

**2. 컨텍스트 스위칭의 기록**
`booksummary`부터 `claude-agent`, 그리고 씨피랩스에서 다루는 다양한 스택들까지. 여러 프로젝트를 동시에 진행하다 보면 컨텍스트 스위칭 비용이 발생합니다. 대시보드에 기록된 `last_msg`를 통해 제가 최근 어떤 기술적 고민(예: Dockerfile 노드 버전 업데이트 등)에 몰입했는지 빠르게 리마인드할 수 있습니다.

### 🚀 마치며

많은 개발자가 코드를 짜는 것에만 집중하지만, 진정한 시니어 엔지니어는 **'자신이 만드는 시스템과 자신의 성장 과정을 어떻게 관찰(Observe)할 것인가'**를 고민해야 합니다.

오늘의 작은 데이터 업데이트는 단순한 `chore` 작업이었지만, 이를 통해 제가 설정한 자동화 루틴이 잘 작동하고 있음을 확인했고, 다음 주에는 어떤 부분에 더 집중해야 할지 방향을 잡을 수 있었습니다.

기록되지 않는 성장은 잊히기 마련입니다. 여러분도 자신만의 '성장 대시보드'를 만들어보시는 건 어떨까요?
