# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어에게 있어 '기록'은 단순히 과거를 남기는 행위가 아니라, 현재의 생산성을 측정하고 미래의 방향성을 결정하는 중요한 데이터 포인트가 됩니다. 저는 개인적으로 제가 수행하는 다양한 프로젝트들의 활동량을 시각화하여 관리하는 대시보드를 운영하고 있습니다. 오늘은 이 대시보드의 데이터를 업데이트하며 느낀 몇 가지 생각들을 공유해보려 합니다.

### 단순한 데이터 업데이트, 그 이상의 의미

오늘 진행한 작업은 겉보기에는 단순한 `dashboard.json` 파일의 업데이트(`chore: Update dashboard data`)였습니다. 하지만 이 JSON 파일이 담고 있는 내용은 제가 최근 어떤 기술적 고민에 집중하고 있었는지를 고스란히 보여줍니다.

이번 커밋의 diff를 살펴보면 몇 가지 흥미로운 지점이 보입니다.

```json
- "name": "claude-agent",
- "last_msg": "log: briefick 11/16 registered on request - explorer 1.5h, cplabs zabbix 1.0h, m",
...
+ "name": "claude-agent",
+ "last_msg": "cpblockchain: release unattached EIP 18.142.89.168 (ex meta-arena) after SG/pref",
+ "commits_7d": 30,
+ "commits_30d": 392
```

특히 `claude-agent` 리포지토리의 활동량이 눈에 띕니다. 최근 30일간 392개의 커밋이 쌓였는데, 이는 제가 AI 에이전트의 자동화와 인프라 최적화에 얼마나 깊게 몰입하고 있는지를 수치로 증명합니다. 씨피랩스에서 진행하는 다양한 블록체인 인프라 작업과 AI를 결합해 효율성을 극대화하려는 시도가 이 숫자들에 녹아있습니다.

### 기술적 결정: 정적 데이터 기반의 대시보드

많은 분이 이런 대시보드를 구축할 때 실시간 API 연동을 생각하시겠지만, 저는 의도적으로 `dashboard.json`이라는 정적 파일을 업데이트하는 방식을 택했습니다. 여기에는 두 가지 이유가 있습니다.

1. **성능과 비용의 최적화**: 깃허브 API의 Rate Limit을 신경 쓰지 않고도 매우 빠른 로딩 속도를 제공하는 정적 페이지(GitHub Pages)를 유지할 수 있습니다.
2. **스냅샷의 가치**: 실시간 데이터는 '현재'만 보여주지만, Git 커밋으로 관리되는 JSON 데이터는 '시간의 흐름'을 보여줍니다. 특정 시점에 내가 어떤 프로젝트에 에너지를 쏟았는지 Git History를 통해 추적할 수 있다는 점이 가장 큰 매력입니다.

### 인사이트: 엔지니어의 '메타 인지'

단순히 코드를 짜는 것을 넘어, 내가 짠 코드의 양과 빈도를 데이터로 확인하는 과정은 일종의 '메타 인지' 과정입니다. 

예를 들어, `booksummary` 리포지토리에서 「황야의 이리」 제작 및 업로드와 같은 개인적인 프로젝트가 꾸준히 유지되고 있는 것을 보며, 기술적 성장뿐만 아니라 인문학적 소양을 쌓는 균형 잡힌 삶을 살고 있는지 스스로 점검하게 됩니다.

### 마치며

20년 넘게 엔지니어로 일하며 깨달은 점은, 결국 훌륭한 아키텍처는 꼼꼼한 기록과 지속적인 피드백 루프에서 나온다는 것입니다. 오늘 업데이트한 이 작은 JSON 파일 하나가 저에게는 다음 한 달의 몰입 지점을 결정하는 나침반이 됩니다.

여러분은 자신의 성장 궤적을 어떻게 기록하고 계신가요? 거창한 도구가 아니더라도, 나만의 방식으로 '데이터화'된 기록을 남겨보시길 추천합니다.
