# [Dev Log] 데이터의 흐름으로 기록하는 성장, 대시보드 자동화의 가치

안녕하세요, 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어로서 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '가시성(Visibility)'입니다. 시스템의 상태를 모니터링하는 것뿐만 아니라, 내가 어떤 방향으로 나아가고 있는지, 내 생산성의 흐름은 어떻게 변하고 있는지를 데이터로 확인하는 과정은 성장을 위한 필수적인 피드백 루프가 됩니다.

오늘은 제 개인 대시보드의 데이터를 업데이트하는 간단한 작업을 진행했습니다. 겉으로 보기에는 단순한 `json` 파일의 수정처럼 보이지만, 그 이면에는 '자동화된 기록'이 주는 인사이트가 담겨 있습니다.

### 🛠️ 오늘의 작업: 대시보드 데이터 동기화

오늘의 핵심 작업은 `src/data/dashboard.json` 파일을 업데이트하여 최근의 개발 활동을 반영하는 것이었습니다.

```diff
-  "generated_at": "2026-11-22T23:00:01.409Z",
+  "generated_at": "2026-11-23T23:00:01.452Z",
...
-          "last_msg": "Auto-generate weekly recap",
+          "last_msg": "Auto-generate daily posts",
```

단순한 날짜 변경 같지만, 이 데이터는 제가 운영하는 여러 레포지토리의 커밋 빈도와 활동량을 추적합니다. 특히 `claude-agent` 레포지토리의 활동량을 보면 흥미로운 점이 발견됩니다.

```diff
-          "commits_7d": 29,
-          "commits_30d": 340
+          "commits_7d": 39,
+          "commits_30d": 349
```

최근 7일간의 커밋 수가 29개에서 39개로 급증한 것을 볼 수 있습니다. 이는 최근 AI 에이전트의 효율성을 높이기 위한 실험적인 시도들이 집중적으로 이루어졌음을 정량적으로 보여줍니다.

### 💡 기술적 결정과 인사이트: 왜 '자동화된 기록'인가?

많은 개발자가 수동으로 TIL(Today I Learned)이나 주간 보고서를 작성합니다. 하지만 바쁜 실무 환경, 특히 씨피랩스에서 CTO로서 복잡한 아키텍처를 설계하고 팀을 리딩하다 보면 기록 자체가 또 다른 '업무'가 되어 부담이 되곤 합니다.

그래서 저는 **'행위가 곧 기록이 되는 시스템'**을 지향합니다. 
Git 커밋이라는 개발자의 기본 행위를 캡처하여 JSON 데이터로 변환하고, 이를 대시보드에 시각화하는 구조입니다. 이번 업데이트 역시 그 자동화 파이프라인의 결과물을 반영한 것입니다.

여기서 얻은 몇 가지 인사이트는 다음과 같습니다.

1. **객관적 자기 객관화**: "요즘 열심히 하고 있다"라는 느낌이 아니라, `commits_7d`라는 숫자를 통해 내 몰입도를 객관적으로 파악할 수 있습니다.
2. **컨텍스트 스위칭의 흔적**: `booksummary`나 `validator` 같은 서로 다른 성격의 프로젝트들 사이에서 내 리소스가 어떻게 분배되고 있는지 한눈에 보입니다.
3. **지속 가능성**: 기록을 위해 따로 시간을 내는 것이 아니라, 개발 프로세스 속에 기록을 녹여냄으로써 '지속 가능한 성장 기록'이 가능해집니다.

### 마치며

블록체인, Web3, AI와 같이 빠르게 변하는 기술 생태계에서 살아남는 방법은 결국 '학습하는 습관'을 시스템화하는 것입니다. 오늘 업데이트한 작은 JSON 파일 하나가 저에게는 단순한 데이터가 아니라, 제가 보낸 시간과 고민의 궤적을 증명하는 로그입니다.

여러분은 자신의 성장을 어떻게 기록하고 계신가요? 도구보다 중요한 것은 '측정 가능한 시스템'을 만드는 것입니다.
