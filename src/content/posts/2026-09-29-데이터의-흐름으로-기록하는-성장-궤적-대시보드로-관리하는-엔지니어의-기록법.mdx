# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어에게 있어 '기록'은 단순히 과거를 저장하는 행위가 아니라, 자신의 성장 궤적을 데이터로 확인하는 과정이라고 생각합니다. 저는 개인적으로 제가 관리하는 여러 프로젝트의 활동량을 수치화하여 대시보드로 관리하고 있는데요. 오늘은 그 대시보드의 데이터를 업데이트하며 느낀 몇 가지 기술적 단상과 인사이트를 공유해보려 합니다.

### 단순한 업데이트, 하지만 그 너머의 의미

오늘 진행한 작업은 겉보기에는 단순한 `dashboard.json` 파일의 업데이트였습니다. 하지만 이 JSON 데이터 속에는 제가 최근 집중하고 있는 기술적 고민들이 고스란히 담겨 있습니다.

특히 이번 커밋의 diff에서 흥미로운 부분은 `heritageradio` 레포지토리의 변경 사항입니다.

```diff
- "last_msg": "[main] docs(CHANGELOG): prod 최신화 배포 기록 — EC2 빌드 호스트..."
+ "last_msg": "[main] fix(probe): DNS 조회도 3회 재시도 — 110 사내 resolver 순간..."
```

단순한 문서 업데이트에서 'DNS 조회 재시도 로직 추가'라는 실제 문제 해결로 흐름이 바뀌었습니다. 분산 시스템이나 네트워크 기반의 서비스를 운영하다 보면, 아주 찰나의 순간 발생하는 DNS resolver의 일시적 오류(Transient Fault)가 전체 시스템의 가용성을 떨어뜨리는 경우가 많습니다. 

여기서 제가 내린 기술적 결정은 **'낙관적 재시도(Optimistic Retry)'** 전략을 도입하는 것이었습니다. 네트워크의 일시적 불안정함은 피할 수 없기에, 이를 코드 레벨에서 3회 정도 재시도하도록 처리함으로써 시스템의 회복 탄력성(Resilience)을 높이는 방향을 택했습니다.

### 데이터로 보는 몰입의 시간

대시보드 데이터를 갱신하며 `claude-agent` 레포지토리의 활동량을 보게 되었습니다. 최근 AI 에이전트와 LLM 오케스트레이션에 깊게 몰입하고 있는데, `commits_7d` 수치가 72회에 달하는 것을 보며 제가 어디에 에너지를 쏟고 있는지 객관적으로 확인할 수 있었습니다.

또한 `booksummary` 프로젝트를 통해 고전소설 시리즈를 하나씩 완결 지어가는 과정은, 복잡한 기술 세계 속에서 인문학적 소양을 쌓으며 균형을 잡으려는 저만의 리프레시 방법이기도 합니다.

### 마치며: 엔지니어의 성장은 '피드백 루프'에 있다

많은 분이 CTO나 시니어 엔지니어라고 하면 거대한 아키텍처 설계만을 생각하시지만, 사실 진짜 실력은 이런 작은 디테일—DNS 재시도 횟수 하나, 일일 커밋 로그 하나—을 챙기는 집요함에서 나온다고 믿습니다.

씨피랩스에서 Web3와 AI의 접점을 찾는 치열한 고민을 이어가듯, 개인적인 공간에서도 끊임없이 '가설 설정 $\rightarrow$ 구현 $\rightarrow$ 데이터 확인'이라는 피드백 루프를 돌리는 것이 제가 20년 넘게 엔지니어로 성장할 수 있었던 비결입니다.

여러분은 오늘 여러분의 성장 궤적에 어떤 데이터를 남기셨나요?
