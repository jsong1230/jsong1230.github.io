# [DevLog] 데이터 자동화가 주는 인사이트: 대시보드 업데이트와 기록의 힘

안녕하세요, 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어로 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 **'측정 가능한 기록'**입니다. 블록체인이나 Web3, AI 같은 최첨단 기술을 다루는 CTO의 역할도 중요하지만, 결국 성장은 내가 무엇을 했고, 어디서 정체되었으며, 어떻게 개선했는지를 객관적인 데이터로 확인하는 과정에서 오기 때문입니다.

오늘은 제 개인 대시보드의 데이터를 업데이트하며, 제가 구축해둔 자동화 파이프라인이 어떻게 작동하고 있는지, 그리고 그 데이터가 저에게 어떤 의미를 주는지 정리해 보려 합니다.

### 단순한 업데이트, 그 이상의 의미

오늘 진행한 작업은 표면적으로는 `dashboard.json` 파일의 데이터를 갱신하는 단순한 `chore` 작업입니다. 하지만 이 JSON 파일은 제 여러 저장소(Repo)의 활동량을 추적하는 일종의 '엔지니어링 건강 검진표'와 같습니다.

```json
// 변경 사항 중 일부
- "last_msg": "Auto-generate weekly book post",
+ "last_msg": "Auto-generate weekly recap",
...
- "commits_7d": 28,
+ "commits_7d": 29,
```

위의 diff를 보시면 알 수 있듯, 주간 리캡(Weekly Recap) 자동 생성 기능이 정상적으로 작동했고, 지난 7일간의 커밋 수가 소폭 상승했습니다. 특히 흥미로운 부분은 `claude-agent` 저장소의 활동입니다.

```json
"last_msg": "kernel: purge 7.0.0-1014 on CPLABS Zabbix and csp-app (no reboot); add kernel101"
```

씨피랩스(CPLABS)의 Zabbix 서버와 앱 환경에서 커널 패치를 진행하고 불필요한 버전을 정리하는 작업이 기록되어 있습니다. 인프라의 안정성을 유지하기 위해 커널을 관리하는 세밀한 작업들이 이렇게 데이터로 남을 때, 비로소 '관리되고 있다'는 확신이 듭니다.

### 기술적 결정: 왜 자동화된 대시보드인가?

많은 개발자가 수동으로 업무 일지를 씁니다. 하지만 바쁜 CTO의 일정 속에서 수동 기록은 금방 누락되기 마련입니다. 그래서 저는 **'활동 데이터의 자동 수집 $\rightarrow$ JSON 저장 $\rightarrow$ 정적 페이지 렌더링'** 구조를 선택했습니다.

1. **최소한의 마찰(Frictionless):** 개발자가 따로 기록할 필요 없이 Git 커밋 로그 자체가 데이터가 됩니다.
2. **객관성:** "열심히 했다"라는 주관적 느낌이 아니라, `commits_7d`, `activity` 배열 같은 수치로 제 상태를 확인합니다.
3. **맥락 유지:** `last_msg`를 통해 당시 어떤 고민을 하며 코드를 짰는지 빠르게 리마인드할 수 있습니다.

### 마치며: 기록은 기억을 이긴다

이번 업데이트를 통해 다시 한번 느낀 점은, 작은 자동화 하나가 주는 심리적 안정감과 성취감입니다. `booksummary` 저장소에서 발자크의 「고리오 영감」 제작 건이 업데이트된 것을 보며, 기술적 작업 외에도 인문학적 소양을 쌓는 루틴이 잘 지켜지고 있음을 확인했습니다.

씨피랩스에서 복잡한 Web3 인프라와 AI 에이전트를 설계하는 일도 중요하지만, 결국 그 모든 복잡함을 이기는 것은 단순하고 꾸준한 기록의 힘이라고 믿습니다. 여러분도 자신만의 '엔지니어링 대시보드'를 만들어 보시는 건 어떨까요?

**오늘의 인사이트:** 
*데이터는 거짓말을 하지 않는다. 다만, 그 데이터를 어떻게 수집하고 해석하느냐가 성장의 속도를 결정한다.*
