# [Dev Log] 데이터의 흐름으로 기록하는 나의 개발 궤적: 대시보드 업데이트의 의미

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어로서 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '가시성(Visibility)'입니다. 복잡한 시스템의 상태를 한눈에 파악할 수 있는 모니터링 툴이 중요하듯, 개인의 성장과 작업 흐름 역시 데이터로 시각화했을 때 비로소 객관적인 회고가 가능하기 때문입니다.

오늘 저는 제가 운영 중인 개인 대시보드의 데이터를 업데이트했습니다. 단순한 JSON 파일의 수정처럼 보일 수 있지만, 그 이면에는 제가 지향하는 '지속 가능한 개발 습관'에 대한 고민이 담겨 있습니다.

### 오늘의 작업: 대시보드 데이터 동기화

오늘 진행한 작업은 `src/data/dashboard.json` 파일을 최신화하는 것이었습니다. 이 파일은 제가 관리하는 여러 리포지토리의 커밋 활동, 최근 메시지, 브랜치 상태 등을 수집하여 시각화하는 대시보드의 소스 데이터입니다.

```json
// 변경 전
"generated_at": "2026-10-27T23:00:01.446Z",
// 변경 후
"generated_at": "2026-10-28T23:00:01.120Z",
```

단순히 날짜가 바뀐 것이 아니라, 지난 24시간 동안 제가 어떤 기술적 고민을 했고 어디에 시간을 쏟았는지가 데이터로 치환되어 기록된 것입니다.

### 데이터가 말해주는 인사이트

이번 diff에서 흥미로운 점은 관리하는 리포지토리의 구성 변화와 활동 패턴입니다. 

1. **집중과 선택**: 기존의 `meta-auth-service` 작업 대신 `metadium_homepage` 관련 Renovate 설정 작업이 추가되었습니다. 이는 현재 제가 인프라의 안정성과 의존성 관리(Dependency Management)라는 운영적 효율성에 집중하고 있음을 보여줍니다.
2. **일관된 리듬**: `jsong1230.github.io` 리포지토리의 `activity` 배열을 보면 매일 꾸준한 수치의 커밋이 발생하고 있습니다. Web3나 AI 같은 빠르게 변하는 분야에서 살아남는 유일한 방법은 결국 '매일 조금씩 기록하고 학습하는 루틴'임을 다시 한번 확인합니다.
3. **자동화의 가치**: `last_msg`에 나타난 "Auto-generate daily posts"라는 문구처럼, 반복적인 데이터 수집과 업데이트를 자동화함으로써 저는 더 본질적인 아키텍처 설계와 기술적 의사결정에 시간을 할애할 수 있게 되었습니다.

### 마치며: 엔지니어에게 '기록'이란 무엇인가

많은 주니어 엔지니어들이 "코드를 짜는 것"만이 개발이라고 생각합니다. 하지만 시니어, 그리고 CTO의 관점에서 개발은 **'문제를 정의하고, 해결하고, 그 과정을 기록하여 자산화하는 것'**입니다.

오늘 제가 업데이트한 이 작은 JSON 파일은 단순한 로그가 아니라, 제가 씨피랩스에서 그리고 개인적으로 어떤 기술적 궤적을 그려왔는지를 증명하는 '디지털 발자취'와 같습니다. 여러분도 자신만의 대시보드를 만들어보시길 권합니다. 내가 어디서 정체되어 있고, 어디서 가속도를 내고 있는지 데이터로 확인하는 순간, 성장의 속도는 비약적으로 빨라질 것입니다.

내일은 또 어떤 데이터가 저의 성장 곡선을 그려낼지 기대됩니다.
