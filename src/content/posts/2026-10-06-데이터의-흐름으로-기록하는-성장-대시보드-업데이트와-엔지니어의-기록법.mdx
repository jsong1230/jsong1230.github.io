# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어에게 있어 '기록'은 단순히 과거를 남기는 행위가 아니라, 현재의 나를 객관적으로 바라보게 하는 '피드백 루프'와 같습니다. 저는 개인적으로 제가 운영하는 여러 프로젝트의 활동 지표를 대시보드 형태로 시각화하여 관리하고 있습니다. 오늘은 이 대시보드의 데이터를 업데이트하며 느낀 몇 가지 인사이트를 공유해보려 합니다.

### 단순한 데이터 업데이트, 그 이상의 의미

오늘 진행한 작업은 `dashboard.json` 파일을 업데이트하는 간단한 `chore` 작업이었습니다. 하지만 이 작은 JSON 파일의 변경 사항(diff)을 살펴보면, 최근 제가 어디에 집중하고 있는지, 그리고 기술적인 관심사가 어떻게 이동하고 있는지가 고스란히 드러납니다.

특히 흥미로운 부분은 `claude-agent` 프로젝트의 최신 커밋 메시지입니다.

```json
"last_msg": "m1.2.1: cplabs gate-1 mainnet pass received; prepare t-exp01/t-api01 swap script"
```

씨피랩스의 메인넷 통과(mainnet pass)라는 중요한 마일스톤을 달성하고, 이를 위해 인프라 스왑 스크립트를 준비하는 과정이 기록되어 있습니다. Web3와 블록체인 분야에서 메인넷 런칭은 기술적 완성도뿐만 아니라 운영의 안정성이 극도로 요구되는 작업입니다. 단순한 코드 한 줄의 변경보다, 이러한 '상태의 변화'를 기록하고 추적하는 것이 실제 운영 환경에서는 훨씬 중요합니다.

### 기술적 결정: 정적 데이터 기반의 대시보드

많은 분이 실시간 대시보드를 위해 복잡한 DB와 API 서버를 구축하곤 합니다. 하지만 저는 개인용 대시보드에 한해서는 **'정적 데이터 파일(JSON) + 자동화 스크립트'** 조합을 선택했습니다. 

이 결정의 이유는 명확합니다.
1. **오버헤드 최소화**: 단순한 지표 확인을 위해 서버를 띄우고 유지보수하는 비용을 줄이고 싶었습니다.
2. **버전 관리**: Git을 통해 데이터의 변경 이력을 관리함으로써, 특정 시점에 내가 어떤 프로젝트에 얼마나 몰입했는지 히스토리를 추적할 수 있습니다.
3. **배포의 간결함**: GitHub Pages와 같은 정적 호스팅만으로도 충분히 빠르게 정보를 확인할 수 있습니다.

### 기록이 주는 인사이트

이번 업데이트에서 `commits_7d`(최근 7일간의 커밋 수) 수치가 변하는 것을 보며, 최근의 리듬을 점검했습니다. 어떤 주에는 특정 프로젝트에 몰입하여 수치가 치솟고, 어떤 주에는 설계와 고민의 시간이 길어지며 수치가 낮아지기도 합니다. 

중요한 것은 '숫자의 높고 낮음'이 아니라, **'내가 의도한 방향으로 리소스가 투입되고 있는가'**를 확인하는 것입니다. 씨피랩스의 메인넷 준비와 같은 핵심 과제에 적절한 에너지가 배분되고 있는지를 데이터로 확인하는 과정은 CTO로서의 매니지먼트 관점에서도 매우 유용한 습관입니다.

### 마치며

20년 넘게 엔지니어로 살아오며 깨달은 점은, 결국 최고의 도구는 '나에게 가장 잘 맞는 도구'라는 것입니다. 거창한 시스템이 아니더라도, JSON 파일 하나에 담긴 나의 활동 기록이 저에게는 가장 강력한 성장의 지표가 됩니다.

여러분은 자신의 성장을 어떻게 기록하고 계신가요? 때로는 복잡한 툴보다 단순한 텍스트 파일 하나가 더 깊은 통찰을 줄 때가 있습니다.
