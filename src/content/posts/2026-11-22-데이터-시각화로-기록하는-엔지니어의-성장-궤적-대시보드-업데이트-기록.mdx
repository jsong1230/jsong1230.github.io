# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어에게 있어 '기록'은 단순한 메모 이상의 의미를 갖습니다. 내가 어떤 고민을 했고, 어떤 기술적 결정을 내렸으며, 시간이 흐르며 어떻게 성장했는지를 보여주는 가장 객관적인 지표가 되기 때문입니다. 저는 개인적으로 저의 개발 활동량을 시각화하여 보여주는 대시보드를 운영하고 있는데, 오늘 그 데이터를 업데이트하며 몇 가지 생각을 정리해 보았습니다.

### 오늘의 작업: 대시보드 데이터 동기화

오늘 진행한 작업은 단순해 보이지만 저에게는 중요한 루틴인 `dashboard.json` 업데이트였습니다. 깃허브의 여러 레포지토리에서 발생하는 커밋 활동과 메시지를 수집해 JSON 형태로 저장하고, 이를 통해 나의 주간/월간 활동성을 모니터링하는 시스템입니다.

이번 업데이트에서 흥미로운 점은 제가 현재 집중하고 있는 프로젝트들의 '온도'가 고스란히 드러난다는 것입니다.

```json
// src/data/dashboard.json 변경 사항 중 일부
- "last_msg": "Auto-generate daily posts",
+ "last_msg": "Auto-generate weekly book post",
...
- "last_msg": "feat: 「바람이 분다, 가라」(한강) 제작·업로드",
+ "last_msg": "feat: 「등대로」(버지니아 울프) 제작·업로드",
```

### 기술적 결정과 인사이트: '자동화'와 '정성적 기록'의 조화

저는 씨피랩스에서 수많은 복잡한 시스템을 설계하고 운영해 왔지만, 개인 프로젝트에서는 **'최소한의 유지보수 비용으로 최대의 가시성을 확보하는 것'**에 집중합니다.

1. **데이터 구조의 단순화**: 복잡한 DB를 구축하는 대신 JSON 파일 하나로 상태를 관리합니다. 이는 정적 사이트 생성기(SSG) 환경에서 빌드 속도를 최적화하고, Git 히스토리 자체가 데이터의 변경 이력(Audit Log)이 되게 만드는 전략입니다.
2. **정성적 데이터의 결합**: 단순히 커밋 횟수(`commits_7d`, `commits_30d`)라는 정량적 수치만 남기는 것이 아니라, `last_msg`를 통해 당시 내가 무엇에 몰입했는지 기록합니다. 예를 들어, 이번 업데이트에서는 한강 작가의 작품에서 버지니아 울프의 「등대로」로 독서 기록이 이어지는 것을 볼 수 있습니다. 이는 기술적 성장뿐만 아니라 인문학적 소양을 쌓으려는 저의 개인적인 지향점이 반영된 결과입니다.

### 마치며: 엔지니어의 대시보드는 곧 '지도'다

`claude-agent` 레포지토리의 활동량(`commits_30d: 343`)을 보면 최근 AI 에이전트와 자동화 툴링에 얼마나 많은 에너지를 쏟고 있는지 알 수 있습니다. 반면, `validator`나 다른 인프라 관련 레포지토리는 안정기에 접어들어 낮은 활동성을 보이고 있죠.

이렇게 데이터를 통해 나의 상태를 객관화하면, 내가 지금 어디에 치우쳐 있는지, 혹은 놓치고 있는 부분은 없는지 판단하는 '지도'가 됩니다. 20년 넘게 엔지니어로 살아오며 느낀 점은, 결국 **측정할 수 없는 것은 개선할 수 없다**는 것입니다.

작은 JSON 파일 하나일지 모르지만, 이 데이터들이 쌓여 제가 나아갈 다음 방향을 제시해 줄 것이라 믿습니다. 내일은 또 어떤 기록이 이 대시보드에 새겨질지 기대됩니다.
