# [Dev Log] 데이터의 흐름으로 기록하는 엔지니어의 일상: 대시보드 자동화와 회고

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한(Jeffrey)입니다.

엔지니어에게 있어 '기록'은 단순한 메모 이상의 의미를 갖습니다. 내가 어떤 고민을 했고, 어떤 기술적 결정을 내렸으며, 시간이 흐르며 어떻게 성장했는지를 보여주는 가장 객관적인 지표가 되기 때문입니다. 저는 평소에 제가 관리하는 리포지토리들의 활동량과 커밋 로그를 시각화하여 관리하는 개인 대시보드를 운영하고 있습니다.

오늘 진행한 작업은 간단해 보이지만, 저에게는 중요한 의미가 있는 `dashboard.json` 데이터 업데이트 작업이었습니다.

### 🛠 오늘의 작업: 대시보드 데이터 동기화

오늘의 주요 변경 사항은 제가 운영 중인 여러 프로젝트의 최신 상태를 반영하는 것이었습니다. Git diff를 보면 단순한 JSON 값의 변경처럼 보이지만, 그 이면에는 제가 최근 집중하고 있는 기술적 관심사들이 고스란히 담겨 있습니다.

```json
// src/data/dashboard.json 변경 부분
- "last_msg": "Auto-generate weekly book post",
+ "last_msg": "Auto-generate weekly recap",
...
- "last_msg": "docs: 10-26 Zabbix runbook order...",
+ "last_msg": "ops(log): 10-25 mainnet gmet adhoc status, all normal (pre-cutover baseline)",
```

특히 흥미로운 점은 `claude-agent` 리포지토리의 활동량입니다. 최근 AI 에이전트를 활용한 운영 자동화에 깊은 관심을 두고 있는데, `commits_30d` 수치가 288회에 달할 정도로 활발하게 실험과 개선을 반복하고 있음을 확인할 수 있습니다. 

또한, `ops(log)` 메시지에서 볼 수 있듯이 메인넷 컷오버(Cut-over) 전 베이스라인을 확인하는 작업 등 실무적인 운영 안정성 확보를 위한 노력들이 데이터에 그대로 투영되어 있습니다.

### 💡 기술적 결정과 인사이트: '자동화된 회고'의 힘

이번 업데이트 과정에서 제가 내린 작은 결정 중 하나는 'Weekly Book Post'에서 'Weekly Recap'으로 자동 생성 로직의 성격을 확장한 것입니다. 

단순히 읽은 책을 정리하는 것을 넘어, 한 주간의 개발 작업, 해결한 이슈, 그리고 씨피랩스에서 고민했던 기술적 아키텍처들을 통합적으로 회고하는 시스템을 구축하고 싶었습니다. 20년 넘게 엔지니어로 살아오며 깨달은 점은, **"측정할 수 없으면 개선할 수 없다"**는 것입니다. 

나의 커밋 빈도, 수정하는 코드의 양, 그리고 메시지의 성격(feat, fix, chore, ops 등)을 데이터화하여 대시보드로 보는 과정은 저 스스로에게 다음과 같은 인사이트를 줍니다.

1. **리소스 배분의 최적화**: 내가 현재 AI 연구에 너무 치우쳐 있는지, 혹은 운영 안정화에 충분한 시간을 쓰고 있는지 객관적으로 파악할 수 있습니다.
2. **성취감의 시각화**: 때로는 진전이 없다고 느껴지는 날에도, 누적된 `commits_30d` 숫자를 보며 꾸준함의 가치를 확인합니다.
3. **컨텍스트 스위칭의 기록**: 여러 프로젝트를 동시에 핸들링하는 CTO로서, 각 프로젝트의 `last_msg`를 통해 빠르게 당시의 맥락을 복구할 수 있습니다.

### 마치며

단순한 `chore` 커밋 하나일지 모르지만, 이 데이터들이 모여 저라는 엔지니어의 히스토리가 됩니다. Web3와 AI라는 거대한 흐름 속에서 중심을 잡기 위해, 저는 앞으로도 이렇게 저만의 '데이터 기반 회고'를 계속 이어가려 합니다.

오늘 여러분의 Git 그래프는 어떤 색으로 채워졌나요? 기록하는 습관이 결국 더 나은 코드를 만든다고 믿습니다.
