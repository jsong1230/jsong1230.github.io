# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한입니다.

엔지니어에게 있어 '기록'은 단순히 과거를 남기는 행위가 아니라, 현재의 나를 객관화하고 미래의 방향성을 설정하는 중요한 피드백 루프입니다. 저는 개인적인 대시보드를 통해 제가 관리하는 여러 프로젝트의 활동량과 커밋 로그를 시각화하여 추적하고 있습니다.

오늘 진행한 작업은 단순해 보이지만, 제 개발 철학이 담겨 있는 `dashboard.json` 데이터 업데이트 작업이었습니다.

### 🛠 오늘의 작업: 대시보드 데이터 동기화

오늘의 주요 변경 사항은 제가 운영 중인 여러 저장소(Repository)의 최신 활동 데이터를 갱신하는 것이었습니다. 

```json
// src/data/dashboard.json 변경 부분
+ {
+   "name": "validator",
+   "last_date": "2026-10-23",
+   "last_msg": "일일 요약 메모리 기준점 10/20 으로 갱신(ParityDB 전환 후 정체",
+   "branch": "master",
+   "activity": [0, 1, 0, 0, 0, 1, 0],
+   "commits_7d": 3,
+   "commits_30d": 34
+ }
```

단순한 JSON 파일 수정처럼 보이지만, 이 데이터가 의미하는 바는 큽니다. 특히 `validator` 프로젝트의 업데이트 내역을 보면 "ParityDB 전환 후 정체"라는 메모가 보입니다. 이는 기술적인 전환 과정에서 발생한 병목 현상을 기록한 것인데, 이렇게 로그를 남겨두면 나중에 어떤 시점에 어떤 고민을 했는지 명확하게 추적할 수 있습니다.

### 💡 기술적 결정과 인사이트

저는 대시보드 데이터를 관리할 때 두 가지 원칙을 가지고 있습니다.

**첫째, 정량적 데이터와 정성적 데이터의 결합입니다.**
단순히 `commits_7d` 같은 숫자만 기록하는 것이 아니라, `last_msg`를 통해 당시의 핵심 맥락(Context)을 함께 저장합니다. 숫자는 '얼마나' 했는지를 알려주지만, 메시지는 '왜' 했는지를 알려주기 때문입니다.

**둘째, 자동화와 수동 기록의 조화입니다.**
`jsong1230.github.io` 저장소의 로그를 보면 `Auto-generate daily posts`라는 메시지가 보입니다. 반복적인 데이터 수집은 자동화하되, 최종적인 데이터 검토와 의미 부여는 제가 직접 수행합니다. 모든 것을 자동화하려는 욕심보다, 자동화가 주는 효율성을 기반으로 '인사이트를 도출하는 시간'을 확보하는 것이 시니어 엔지니어의 역할이라고 생각합니다.

### 🚀 마치며

오늘의 커밋 로그를 다시 살펴보니 `claude-agent` 프로젝트의 활동량이 여전히 높고, `booksummary`를 통해 「지구 끝의 온실」이라는 책을 정리하며 지적 외연을 넓히는 과정이 고스란히 담겨 있더군요.

블록체인, Web3, AI라는 거대한 기술적 파도 속에서 길을 잃지 않는 방법은 결국 '나만의 기록'을 쌓아가는 것입니다. 씨피랩스에서도 팀원들과 함께 이러한 기록의 문화를 정착시켜, 개개인의 성장이 회사의 기술적 자산으로 이어지는 선순환 구조를 만들고자 합니다.
