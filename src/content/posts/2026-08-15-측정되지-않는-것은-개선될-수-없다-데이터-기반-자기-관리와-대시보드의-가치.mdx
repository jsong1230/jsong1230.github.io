# [Dev Log] 데이터의 흐름으로 기록하는 성장: 대시보드 업데이트와 자동화의 가치

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한입니다.

엔지니어로서 20년 넘게 다양한 프로젝트를 리딩하며 깨달은 점 중 하나는, **'측정되지 않는 것은 개선될 수 없다'**는 것입니다. 복잡한 블록체인 아키텍처를 설계하거나 AI 모델을 도입하는 거창한 작업도 중요하지만, 정작 나 자신의 생산성과 작업 흐름을 객관적으로 바라보는 시스템을 갖추는 것이 지속 가능한 성장의 핵심이더군요.

오늘은 제 개인 대시보드의 데이터를 업데이트하며, 제가 지향하는 '데이터 기반의 자기 관리'에 대해 짧게 기록해보려 합니다.

### 단순한 데이터 업데이트, 그 이상의 의미

오늘의 작업은 겉보기에 매우 단순합니다. `dashboard.json` 파일의 내용을 최신 상태로 갱신하는 `chore` 작업이었죠. 하지만 이 JSON 파일 하나에는 제가 최근 어떤 기술적 고민을 했고, 어디에 시간을 쏟았는지가 고스란히 담겨 있습니다.

```diff
-  "generated_at": "2026-08-13T23:00:01.105Z",
+  "generated_at": "2026-08-14T23:00:01.689Z",
```

매일 자정, 자동화된 스크립트가 제 깃허브 활동을 수집해 이 파일을 생성합니다. 이번 diff에서 특히 흥미로운 부분은 `claude-agent` 리포지토리의 변화입니다.

```diff
+          "last_msg": "docs: wrap up 2026-08-14 with EOD summary and phase-3 SSH key plan",
+          "activity": [
+            11,
+            15,
+            4,
+            5,
+            7,
+            13,
+            0
+          ],
+          "commits_7d": 63,
```

최근 집중하고 있는 AI 에이전트 관련 작업(`claude-agent`)의 커밋 빈도와 활동량이 급증한 것을 볼 수 있습니다. 특히 'Phase-3 SSH key plan'과 같은 구체적인 인프라 설계 단계로 진입했음을 데이터가 증명해주고 있죠. 단순히 "요즘 열심히 하고 있다"는 느낌이 아니라, 7일간 63개의 커밋이라는 숫자로 제 몰입도를 확인하는 과정입니다.

### 기술적 결정: 왜 자동화된 JSON 대시보드인가?

많은 분이 화려한 분석 툴을 사용하지만, 저는 **'최소한의 오버헤드'**와 **'Git 기반의 이력 관리'**를 선택했습니다.

1. **정적 데이터의 힘**: API 호출 없이 JSON 파일만으로 대시보드를 렌더링함으로써 로딩 속도를 극대화하고 인프라 비용을 제로로 만들었습니다.
2. **버전 관리**: 제 생산성 지표 자체가 Git 커밋 이력으로 남습니다. 시간이 흐른 뒤 "내가 2026년 8월에는 어떤 리듬으로 일했지?"를 `git log`를 통해 회고할 수 있습니다.
3. **피드백 루프**: `activity` 배열에 기록된 일별 커밋 수를 보며, 특정 요일에 에너지가 떨어지거나 과몰입하는 패턴을 발견하고 조절할 수 있습니다.

### 마치며: 엔지니어의 루틴이 만드는 차이

씨피랩스에서 수많은 팀원과 협업하며 강조하는 것 중 하나가 바로 '가시성(Visibility)'입니다. 시스템의 상태가 투명하게 보일 때 우리는 정확한 의사결정을 내릴 수 있습니다. 이는 개인의 성장 관리에서도 마찬가지입니다.

오늘의 작은 `chore` 작업은 단순한 데이터 갱신이었지만, 저에게는 현재의 궤도를 점검하고 내일의 우선순위를 설정하는 중요한 리추얼(Ritual)과 같습니다. 여러분은 자신의 성장을 어떻게 측정하고 계신가요?

거창한 툴이 아니더라도, 나만의 '데이터 포인트'를 만들어 기록해 보시길 권합니다. 그 작은 기록들이 모여 결국 대체 불가능한 전문성을 만드는 밑거름이 됩니다.
