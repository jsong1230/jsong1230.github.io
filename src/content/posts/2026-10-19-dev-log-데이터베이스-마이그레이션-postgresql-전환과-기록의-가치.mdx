## [Dev Log] 데이터베이스 마이그레이션의 여정: PostgreSQL로의 전환과 기록의 의미

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한입니다.

엔지니어로서 가장 긴장되면서도 동시에 희열을 느끼는 작업 중 하나가 바로 '데이터베이스 마이그레이션'입니다. 시스템의 심장을 교체하는 일과 같기에 신중함이 요구되죠. 오늘은 제가 개인적으로 관리하는 대시보드 데이터를 업데이트하며, 최근 씨피랩스에서 진행 중인 기술적 전환점들을 되짚어보려 합니다.

### 오늘의 작업: 대시보드 데이터 업데이트

오늘의 Git 커밋은 단순한 `chore: Update dashboard data`로 보일 수 있지만, 그 내부의 `diff`를 살펴보면 제가 최근 어떤 고민을 하며 코드를 작성했는지 고스란히 드러납니다.

```json
- "last_msg": "build: pin test dependency org.web3j:crypto to 4.8.7",
- "branch": "build/pin-web3j-java8",
+ "last_msg": "db: add PostgreSQL driver and make native query portable (current_date)",
+ "branch": "migration/postgresql",
```

최근 여러 레포지토리(`metadium-attestator`, `mykeepin-identity-attestator` 등)에서 공통적으로 나타나는 변화는 바로 **PostgreSQL로의 마이그레이션**입니다. 단순히 드라이버를 추가하는 것을 넘어, `native query`를 포터블하게 만드는 작업, 즉 특정 DB에 종속적인 쿼리를 표준 SQL이나 PostgreSQL 호환 쿼리로 수정하는 과정이 포함되었습니다.

### 기술적 결정과 인사이트: "Portable"의 가치

이번 작업에서 가장 신경 쓴 부분은 **'이식성(Portability)'**입니다. 

많은 개발자가 프레임워크가 제공하는 추상화 계층(ORM 등)에 의존하지만, 성능 최적화를 위해 Native Query를 사용하다 보면 특정 DB의 문법에 종속되기 마련입니다. 예를 들어, 날짜를 처리하는 방식이나 캐스팅(`casting elapsed to integer`) 방식은 DB마다 미묘하게 다릅니다.

제가 이번 마이그레이션에서 내린 결정은 다음과 같습니다.
1. **최소한의 변경으로 최대의 호환성 확보**: 기존 비즈니스 로직을 흔들지 않으면서, DB 엔진이 바뀌어도 동작할 수 있도록 쿼리 표준화를 진행했습니다.
2. **의존성 고정(Dependency Locking)**: `deps: lock pg 8.7.3` 커밋에서 볼 수 있듯, 레거시 환경(Node 10 등)과의 호환성을 유지하기 위해 라이브러리 버전을 엄격하게 관리했습니다. 인프라 전환기에는 '최신 버전'보다 '검증된 버전'이 훨씬 중요하기 때문입니다.

### 기록이 주는 힘

개인 대시보드에 매일의 활동량을 기록하는 이유는 단순한 자기만족이 아닙니다. 20년 넘게 엔지니어로 살아오며 느낀 점은, **"내가 어떤 문제를 풀었는가"에 대한 기록이 곧 나의 기술적 자산**이 된다는 것입니다.

오늘 업데이트한 `dashboard.json`의 `activity` 배열에 찍힌 숫자들은 단순한 커밋 횟수가 아니라, PostgreSQL 마이그레이션이라는 하나의 큰 퍼즐을 맞춰가는 과정의 흔적입니다.

### 마치며

Web3와 DID, 그리고 AI가 결합되는 현대의 아키텍처에서 데이터의 무결성과 저장소의 안정성은 기본 중의 기본입니다. 씨피랩스에서도 이러한 기본기를 바탕으로 더 견고한 시스템을 구축해 나가고 있습니다.

마이그레이션이라는 험난한 과정 속에 있지만, 하나씩 해결해 나가는 이 과정이야말로 엔지니어가 성장하는 가장 빠른 길이라고 믿습니다. 내일은 또 어떤 문제를 풀게 될지 기대됩니다.
