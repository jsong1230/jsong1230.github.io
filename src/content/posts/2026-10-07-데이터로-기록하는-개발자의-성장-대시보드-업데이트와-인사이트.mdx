# [Dev Log] 데이터의 흐름으로 읽는 나의 개발 리듬: 대시보드 업데이트와 인사이트

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어로서 20년 넘게 코드를 작성하며 깨달은 점 중 하나는, 단순히 기능을 구현하는 것보다 '내가 어디에 시간을 쓰고 있는가'를 가시화하는 것이 성장에 훨씬 도움이 된다는 점입니다. 그래서 저는 개인적인 개발 활동을 추적하는 대시보드를 운영하고 있습니다.

오늘 진행한 작업은 단순해 보이지만, 저에게는 꽤 의미 있는 **대시보드 데이터 업데이트(`chore: Update dashboard data`)** 작업이었습니다.

### 📊 데이터가 말해주는 오늘의 우선순위

오늘 업데이트한 `dashboard.json`의 diff를 보면 제가 최근 어떤 기술적 고민에 집중하고 있는지 명확히 드러납니다. 특히 흥미로운 부분은 `go-delegator`와 `metadium-explorer-stack` 레포지토리의 변경 사항입니다.

```json
{
  "name": "go-delegator",
  "last_msg": "merge: 노드 failover + 공개 forward 허용 목록 (mainnet 백엔드 이중화)",
  "branch": "develop"
},
{
  "name": "metadium-explorer-stack",
  "last_msg": "feat(delegator): 백엔드 이중화 배포 스크립트",
  "branch": "master"
}
```

최근 씨피랩스에서 진행 중인 인프라 고도화 작업의 일환으로 **'백엔드 이중화(Redundancy)'**와 **'Failover'** 메커니즘을 구현하는 데 집중하고 있습니다. 블록체인 노드나 델리게이터(Delegator)와 같은 핵심 인프라는 단 1분의 다운타임도 치명적입니다. 따라서 단순한 배포를 넘어, 장애 발생 시 어떻게 자동으로 트래픽을 전환하고 가용성을 확보할 것인가에 대한 기술적 결정을 내리고 이를 스크립트화하는 과정이었습니다.

### 💡 코드 변경에서 얻은 인사이트

이번 업데이트에서 특히 눈에 띄는 지표는 `claude-agent` 레포지토리의 활동량입니다. 

- **`commits_7d`**: 18 $\rightarrow$ 38
- **`activity`**: 특정 일자에 22건의 커밋 집중 발생

최근 AI 에이전트의 자율성을 높이는 실험을 진행 중인데, 데이터 수치가 급증한 것은 그만큼 가설 설정과 검증(Trial and Error)의 사이클이 빠르게 돌아가고 있다는 증거입니다. Web3와 AI의 결합은 이론보다 '실제 동작하는 구현체'를 통해 배우는 것이 훨씬 빠릅니다. 

또한, `booksummary`와 같은 개인 프로젝트의 커밋이 꾸준히 유지되는 것을 보며, 기술적인 딥다이브 외에도 인문학적 소양을 쌓는 '맥락 전환(Context Switching)'이 오히려 메인 업무의 창의성을 높여준다는 것을 다시금 느낍니다.

### 마치며

단순한 JSON 파일의 업데이트였지만, 이를 통해 지난 일주일간의 제 궤적을 복기할 수 있었습니다. 

**인프라의 안정성(Failover) $\rightarrow$ AI의 확장성(Claude-Agent) $\rightarrow$ 개인적 성장(Book Summary)**

이 세 가지 축의 균형을 맞추는 것이 제가 지향하는 시니어 엔지니어이자 CTO로서의 삶입니다. 내일은 또 어떤 데이터가 제 대시보드를 채우게 될지 기대됩니다.
