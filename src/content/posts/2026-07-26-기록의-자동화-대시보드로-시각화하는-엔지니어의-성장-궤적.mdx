# [Insight] 데이터의 흐름으로 기록하는 성장: 대시보드 자동화와 '활동의 시각화'

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한입니다.

엔지니어에게 있어 '기록'은 단순한 메모 이상의 의미를 갖습니다. 내가 어떤 고민을 했고, 어떤 기술적 결정으로 문제를 해결했는지 남기는 과정은 곧 개인의 성장 궤적을 그리는 일과 같기 때문입니다. 하지만 바쁜 실무 속에서 매일 수동으로 기록을 남기는 것은 생각보다 큰 에너지가 소모되는 일입니다.

그래서 저는 제가 관리하는 여러 프로젝트와 리포지토리의 활동 내역을 한눈에 볼 수 있는 **개인용 대시보드 자동화 시스템**을 운영하고 있습니다. 오늘 진행한 작업 역시 이 대시보드의 데이터를 최신화하는 과정이었습니다.

### 🛠 오늘의 작업: 데이터 동기화와 활동 지표 업데이트

오늘의 주요 작업은 `dashboard.json` 파일을 업데이트하여 최근 7일 및 30일간의 커밋 활동과 최신 메시지를 반영하는 것이었습니다. 단순한 데이터 수정처럼 보일 수 있지만, 여기에는 **'지속 가능한 기록 시스템'**에 대한 고민이 담겨 있습니다.

```json
// src/data/dashboard.json 변경 부분
- "last_date": "2026-07-24",
- "last_msg": "Auto-generate daily posts",
+ "last_date": "2026-07-25",
+ "last_msg": "Auto-generate weekly book post",
```

위의 diff에서 볼 수 있듯이, 단순히 날짜가 바뀌는 것이 아니라 `last_msg`를 통해 제가 최근에 어떤 주제(예: 주간 도서 포스팅 자동화)에 집중했는지를 캡처합니다. 

### 💡 기술적 결정과 인사이트: 왜 '데이터 기반' 기록인가?

저는 블록체인, Web3, AI 분야에서 오랫동안 아키텍처를 설계하며 **'신뢰할 수 있는 데이터'**의 중요성을 체감해 왔습니다. 개인의 성장 기록 역시 주관적인 느낌보다는 객관적인 지표(Activity Metrics)로 관리할 때 더 명확한 인사이트를 얻을 수 있다고 믿습니다.

이번 업데이트 과정에서 주목한 점은 다음과 같습니다.

1. **활동의 밀도 측정**: `activity` 배열의 숫자 변화를 통해 특정 기간에 어떤 프로젝트에 리소스가 집중되었는지 파악합니다. 이는 추후 제가 어떤 기술 스택에 더 많은 시간을 투자했는지 분석하는 기초 자료가 됩니다.
2. **자동화의 선순환**: "Auto-generate"라는 메시지가 반복되는 것은, 기록하는 행위 자체를 자동화하여 '기록을 위한 기록'이 아닌 '인사이트를 위한 기록'에 집중하려는 저의 전략입니다.
3. **전체 뷰(Holistic View) 유지**: 씨피랩스에서의 업무뿐만 아니라 개인적인 연구, 오픈소스 기여, 독서 기록 등을 하나의 JSON 구조로 통합 관리함으로써, 삶과 업무의 균형과 조화를 시각적으로 확인합니다.

### 🚀 마치며

20년 넘게 엔지니어로 살아오며 느낀 점은, 결국 최고의 퍼포먼스는 **'자신의 상태를 정확히 메타인지 하는 것'**에서 나온다는 것입니다. 오늘 업데이트한 작은 JSON 파일 하나가 저에게는 단순한 로그가 아니라, 내일의 더 나은 설계를 위한 나침반이 됩니다.

기술적 깊이를 더하는 것만큼이나 중요한 것은, 그 과정을 어떻게 체계적으로 관리하느냐입니다. 여러분은 자신의 성장을 어떻게 기록하고 계신가요?
