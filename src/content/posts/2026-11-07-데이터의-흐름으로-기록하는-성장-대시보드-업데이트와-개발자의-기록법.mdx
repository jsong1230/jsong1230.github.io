## [Insight] 데이터의 흐름으로 기록하는 개발자의 삶: 대시보드 업데이트의 의미

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한입니다.

개발자에게 '기록'은 단순한 메모 이상의 의미를 갖습니다. 우리가 어떤 고민을 했고, 어떤 기술적 결정을 내렸으며, 시간이 흐름에 따라 어떻게 성장했는지를 보여주는 가장 객관적인 지표가 되기 때문입니다. 저는 개인적으로 제가 관리하는 여러 프로젝트의 활동량을 추적하는 자동화된 대시보드를 운영하고 있습니다.

오늘 진행한 작업은 단순해 보이지만, 저에게는 매일의 호흡을 확인하는 중요한 루틴인 `dashboard.json` 데이터 업데이트였습니다.

### 단순한 데이터 갱신, 그 이상의 인사이트

오늘의 커밋 내역을 보면 `src/data/dashboard.json` 파일에서 여러 저장소의 `last_date`, `last_msg`, 그리고 `activity` 배열이 변경된 것을 볼 수 있습니다.

```json
- "last_msg": "feat: 「작은 땅의 야수들」(김주혜) 제작·업로드",
+ "last_msg": "feat: 「백의 그림자」(황정은) 제작·업로드",
```

특히 흥미로운 부분은 `booksummary` 저장소의 변경점입니다. 기술적인 코드 수정은 아니지만, 독서 기록이 업데이트되는 과정을 통해 제가 기술 외적으로 어떤 인풋을 채우고 있는지 확인할 수 있습니다. 엔지니어로서의 성장은 최신 프레임워크를 익히는 것만큼이나, 인문학적 소양을 통해 세상을 바라보는 관점을 넓히는 것에서 온다고 믿습니다.

또한, `claude-agent`와 같은 실험적인 프로젝트의 `commits_7d` 수치가 변동하는 것을 보며, 최근 제가 어떤 도구와 자동화에 몰입하고 있는지를 정량적으로 파악할 수 있었습니다.

### 기술적 결정: 왜 자동화된 데이터 파일인가?

많은 분이 이런 데이터를 DB에 저장하고 API로 호출하는 방식을 생각하시겠지만, 저는 정적 파일(`json`) 기반의 업데이트 방식을 유지하고 있습니다. 여기에는 몇 가지 실무적인 이유가 있습니다.

1. **Zero Infrastructure**: 별도의 서버나 DB 유지 비용 없이 GitHub Pages와 같은 정적 호스팅만으로 대시보드를 구현할 수 있습니다.
2. **Version Control**: 데이터의 변화 자체가 Git 커밋 히스토리에 남습니다. 즉, '데이터의 변경 이력'이 곧 '나의 활동 로그'가 되는 셈입니다.
3. **Performance**: 클라이언트 사이드에서 JSON 파일을 직접 읽어오기 때문에 응답 속도가 매우 빠릅니다.

### 마치며: 기록이 쌓이면 자산이 된다

20년 넘게 엔지니어로 일하며 깨달은 점은, 결국 '지속 가능성'이 가장 중요하다는 것입니다. 거창한 시스템을 구축하는 것보다, 매일 조금씩이라도 자동으로 기록되는 시스템을 만드는 것이 훨씬 강력합니다.

오늘 업데이트한 짧은 JSON 데이터 한 줄이 1년 뒤, 5년 뒤에는 제가 어떤 궤적으로 성장해 왔는지를 증명하는 소중한 자산이 될 것입니다. 여러분도 자신만의 '성장 지표'를 기록하는 시스템을 만들어보시는 건 어떨까요?
