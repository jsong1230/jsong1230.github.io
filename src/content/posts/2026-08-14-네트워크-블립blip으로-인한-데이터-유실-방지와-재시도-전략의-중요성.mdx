# [Ops Log] "일시적인 블립(Blip)이 서비스 장애가 되지 않게 하는 법"

안녕하세요, 씨피랩스의 송주한입니다.

엔지니어로서 가장 허탈할 때가 언제일까요? 아마도 "코드에 버그가 있었던 것도 아니고, 서버가 죽은 것도 아닌데, 아주 잠깐의 네트워크 지연(Blip) 때문에 데이터가 꼬였을 때"가 아닐까 합니다. 오늘 제가 정확히 그 경험을 했고, 이를 해결하며 얻은 인사이트를 공유하고자 합니다.

## 1. 문제의 발견: "왜 1975년 콘텐츠가 어제의 것을 가리키고 있지?"

오늘 오전, 정기 모니터링(hourly verify) 중에 경고가 떴습니다. 특정 에라(era=1975)의 사이클 05 콘텐츠가 누락되었다는 알림이었습니다. 확인해 보니 서비스 중단은 아니었지만, 심각한 **'콘텐츠 stale(노후화)'** 상태였습니다.

원인은 단순했습니다. 새벽 00:06분경, S3로 데이터를 동기화하는 `aws s3 sync` 과정에서 단 한 번, `Could not connect to the endpoint URL`이라는 일시적인 네트워크 오류가 발생했습니다. 

문제는 여기서부터였습니다. **재시도(Retry) 로직이 없었기에**, 이 한 번의 실패가 그대로 확정되었습니다. 결과적으로 해당 구간의 매니페스트 파일이 업데이트되지 않았고, 사용자들은 오늘 콘텐츠가 아닌 어제 콘텐츠를 보게 될 상황이었습니다. 다행히 방송 11시간 전에 발견하여 복구했지만, 가슴을 쓸어내린 순간이었습니다.

## 2. 기술적 결정: 단순하지만 강력한 `run_with_retry` 도입

이 문제의 핵심은 "분산 시스템에서 네트워크 오류는 '상수'이지 '변수'가 아니다"라는 점입니다. 언제든 일어날 수 있는 일이라고 가정하고 설계했어야 했습니다.

저는 즉시 `sync_today_cycle5_to_prod.sh`와 `sync_tomorrow_cycle_to_prod.sh` 스크립트에 재시도 메커니즘을 도입했습니다. 복잡한 라이브러리 대신, 쉘 스크립트 수준에서 제어 가능한 `run_with_retry` 함수를 구현했습니다.

```bash
# 3회 재시도 + 30초 백오프(Backoff) 적용
run_with_retry() {
  local n=1
  until "$@"; do
    if (( n >= SYNC_RETRIES )); then
      echo "  ✗ ${SYNC_RETRIES}회 시도 모두 실패"
      return 1
    fi
    echo "  ⟳ 시도 ${n}/${SYNC_RETRIES} 실패 — ${SYNC_RETRY_WAIT}s 후 재시도"
    sleep "$SYNC_RETRY_WAIT"
    n=$((n + 1))
  done
  return 0
}
```

단순히 다시 실행하는 것이 아니라, `SYNC_RETRY_WAIT`를 통해 적절한 간격을 둠으로써 일시적인 엔드포인트 과부하나 네트워크 불안정 상태가 해소될 시간을 벌어주었습니다. 이제는 한두 번의 블립이 발생하더라도 시스템이 스스로 자가 복구(Self-healing)를 수행하게 됩니다.

## 3. 인사이트: 알림보다 중요한 것은 '자가 복구 능력'

이번 사건에서 흥미로운 점은, 사실 실패 당시 텔레그램 알림은 정상적으로 발송되었다는 것입니다. 하지만 심야 시간이었기에 사람이 인지하기까지 8시간의 공백이 생겼습니다.

여기서 중요한 교훈을 얻었습니다. **"완벽한 알림 시스템보다 더 가치 있는 것은, 사람이 개입하지 않아도 해결되는 자가 복구 로직이다."**

운영 환경(Ops)에서 엔지니어의 수면 시간을 보장하고 서비스 안정성을 높이는 방법은 결국 '실패를 어떻게 정의하고, 어떻게 자동으로 극복하게 하느냐'에 달려 있습니다.

## 마치며

오늘은 S3 동기화 이슈 외에도 블록체인 노드들의 설정 최적화(StaticNodes 적용)와 콘텐츠 파이프라인 관리 등 다양한 작업을 진행했습니다. 

결국 인프라 운영의 묘미는 이러한 작은 틈새를 메워가는 과정에 있는 것 같습니다. "설마 여기서 에러가 나겠어?"라는 생각이 드는 바로 그 지점에 `retry` 로직을 넣으세요. 그것이 여러분의 주말과 잠자리를 지켜줄 것입니다.
