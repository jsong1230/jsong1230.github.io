## [Dev Log] 데이터의 흐름으로 기록하는 개발자의 일상: 대시보드 업데이트와 인사이트

안녕하세요, 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어로 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '가시성(Visibility)'입니다. 복잡한 시스템일수록 현재 어떤 상태인지, 어디서 병목이 발생하는지 한눈에 파악할 수 있는 지표가 필요하죠. 이는 거대한 엔터프라이즈 아키텍처뿐만 아니라, 개인의 개발 생산성을 관리하는 데에도 동일하게 적용됩니다.

오늘은 제 개인 개발 활동을 트래킹하는 `jsong1230.github.io` 대시보드의 데이터를 업데이트했습니다. 단순한 `chore` 작업처럼 보일 수 있지만, 이 데이터들이 쌓여 만드는 '개발 궤적'에는 몇 가지 흥미로운 지점들이 있습니다.

### 데이터가 말해주는 우선순위의 변화

이번 커밋의 핵심은 `src/data/dashboard.json` 파일의 갱신입니다. diff 내용을 살펴보면 제가 최근 어떤 프로젝트에 집중하고 있는지 명확히 드러납니다.

```json
{
  "name": "claude-agent",
  "last_msg": "log: mainnet status check 21:0x - 15 nodes ok, soak 18:05 passed...",
  "commits_7d": 53,
  "commits_30d": 468
}
```

특히 `claude-agent` 프로젝트의 수치가 눈에 띕니다. 최근 7일간 53개의 커밋, 30일 기준으로는 468개의 커밋이 기록되었습니다. 메인넷 상태 체크와 소크 테스트(Soak Test) 결과가 로그에 남겨진 것을 보면, 현재 AI 에이전트의 안정성 확보와 메인넷 통합 단계에 깊게 몰입하고 있음을 알 수 있습니다. 

반면, `metadium-explorer-stack`이나 `heritageradio` 같은 프로젝트들은 유지보수 및 배포 단계(`chore: 서브모듈 머지`, `prod backend+celery 배포`)로 전환되어 커밋 빈도가 조절되고 있습니다.

### 기술적 결정: 왜 '정적 데이터' 기반의 대시보드인가?

누군가는 "왜 API를 통해 실시간으로 가져오지 않고 JSON 파일을 직접 업데이트하느냐"고 물을 수 있습니다. 하지만 저는 여기서 **'단순함의 미학'**과 **'불변성'**을 선택했습니다.

1. **Zero Dependency**: 외부 API 호출 없이 정적 파일만으로 렌더링되므로 로딩 속도가 극도로 빠르고 인프라 비용이 제로에 가깝습니다.
2. **Snapshot 기록**: 실시간 데이터는 '현재'를 보여주지만, Git으로 관리되는 JSON 데이터는 '시간의 흐름'을 기록합니다. 특정 시점에 내가 어떤 고민을 했고, 어떤 프로젝트에 리소스를 투입했는지 Git History를 통해 역추적할 수 있습니다.

### 마치며: 기록하는 습관이 만드는 엔지니어링

씨피랩스에서 CTO로서 수많은 팀을 리딩하며 느낀 점은, 뛰어난 엔지니어는 코드를 잘 짜는 사람이 아니라 **'자신의 작업 흐름을 객관적으로 바라볼 줄 아는 사람'**이라는 것입니다. 

오늘처럼 내 활동 데이터를 수치화하고 시각화하는 과정은 단순한 자기만족이 아닙니다. 내가 어디에 과하게 몰입하고 있는지, 혹은 놓치고 있는 부분은 없는지 판단하는 '메타 인지'의 과정입니다.

여러분도 자신만의 '개발 대시보드'를 만들어보시는 건 어떨까요? 거창한 도구가 아니어도 좋습니다. 작은 기록들이 모여 여러분의 전문성을 증명하는 가장 강력한 포트폴리오가 될 것입니다.
