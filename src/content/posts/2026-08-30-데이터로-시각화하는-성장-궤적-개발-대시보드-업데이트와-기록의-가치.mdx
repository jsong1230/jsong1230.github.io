# [Insight] 데이터의 흐름으로 기록하는 성장: 나의 개발 대시보드 업데이트

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어로서 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '가시성(Visibility)'입니다. 시스템의 상태를 모니터링하는 것뿐만 아니라, 나 자신의 성장 궤적과 작업 패턴을 데이터로 시각화하는 것은 매우 강력한 피드백 루프가 됩니다.

오늘은 제 개인 프로젝트인 `gram-jsong` 대시보드의 데이터를 업데이트했습니다. 단순한 JSON 파일 수정처럼 보일 수 있지만, 이 과정에서 제가 추구하는 '기록의 자동화'와 '데이터 기반의 회고'에 대해 이야기해보고자 합니다.

### 🛠 오늘의 작업: 대시보드 데이터 동기화

오늘 진행한 작업은 매우 심플합니다. `src/data/dashboard.json` 파일을 업데이트하여 최근 7일 및 30일간의 커밋 활동량과 각 레포지토리의 최신 메시지를 갱신한 것입니다.

```json
// 변경 사항 중 일부
- "commits_7d": 78,
- "commits_30d": 349
+ "commits_7d": 99,
+ "commits_30d": 360
```

특히 `claude-agent` 레포지토리의 활동량이 눈에 띕니다. 7일간의 커밋 수가 78개에서 99개로 급증했는데, 이는 최근 AI 에이전트의 워크플로우 최적화와 NAT 마이그레이션 같은 인프라 작업에 집중했기 때문입니다.

### 💡 기술적 결정과 인사이트: 왜 '데이터'인가?

저는 단순히 "열심히 했다"는 느낌보다 "지난주보다 활동량이 20% 증가했다"는 수치를 신뢰합니다. 이를 위해 제가 선택한 방식은 **'코드로서의 대시보드(Dashboard as Code)'**입니다.

1. **자동화된 트래킹**: 매번 수동으로 기록하는 것이 아니라, 깃허브 API 등을 통해 데이터를 추출하고 JSON 형태로 저장함으로써 기록에 드는 비용을 최소화했습니다.
2. **맥락의 보존**: `last_msg` 필드를 통해 당시 어떤 고민을 했는지 짧은 로그를 남깁니다. 예를 들어, 오늘 업데이트된 `booksummary` 레포지토리의 `"verify: 서울 1964년 겨울 3회차... '변동은 항상 상승' 가설"` 같은 메시지는 단순한 커밋 로그를 넘어, 제가 탐구하고 있는 가설과 생각의 흐름을 보여줍니다.

### 🚀 마치며

씨피랩스에서 수많은 복잡한 아키텍처를 설계하고 Web3와 AI의 접점을 찾는 일을 하고 있지만, 결국 모든 거대한 성취는 매일의 작은 커밋들이 모여 만들어진다고 믿습니다. 

데이터는 거짓말을 하지 않습니다. 때로는 정체된 그래프를 보며 자극을 받고, 때로는 가파른 상승 곡선을 보며 성취감을 느낍니다. 여러분도 자신만의 '성장 대시보드'를 만들어보시는 건 어떨까요? 

기록되지 않은 노력은 잊혀지지만, 데이터로 남은 노력은 자산이 됩니다.
