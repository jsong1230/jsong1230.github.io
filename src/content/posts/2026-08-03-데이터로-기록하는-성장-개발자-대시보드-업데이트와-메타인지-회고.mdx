# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장: 대시보드 업데이트와 회고

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어에게 있어 '기록'은 단순한 메모 이상의 의미를 갖습니다. 제가 20년 넘게 개발자의 길을 걸으며 깨달은 점 중 하나는, 내가 어떤 고민을 했고 어떤 리듬으로 작업했는지를 수치화해서 보는 것이 메타인지를 높이는 데 굉장히 효과적이라는 것입니다. 

오늘은 제 개인 대시보드의 데이터를 업데이트하며, 최근의 작업 패턴을 돌아보는 시간을 가졌습니다. 단순한 `chore` 커밋처럼 보일 수 있지만, 그 안에 담긴 데이터의 변화가 주는 인사이트를 공유해보고자 합니다.

### 🛠 오늘의 작업: 대시보드 데이터 동기화

오늘 진행한 작업은 `src/data/dashboard.json` 파일을 최신화하는 것이었습니다. 제 대시보드는 여러 레포지토리의 커밋 활동과 빈도를 자동으로 추적하여 시각화해주는 구조입니다.

```json
// 변경 사항 중 일부
- "last_msg": "Auto-generate weekly book post",
+ "last_msg": "Auto-generate weekly recap",
...
- "commits_7d": 46,
- "commits_30d": 71
+ "commits_7d": 48,
+ "commits_30d": 73
```

단순히 날짜와 숫자가 바뀌는 작업이지만, 저는 이 `diff`를 통해 최근 제가 어디에 집중하고 있는지를 읽어냅니다.

### 💡 기술적 결정과 인사이트

**1. 자동화된 회고 시스템의 가치**
최근 `last_msg`가 "weekly book post"에서 "weekly recap"으로 변경된 것을 볼 수 있습니다. 단순히 읽은 책을 정리하는 것을 넘어, 한 주간의 기술적 성취와 시행착오를 정리하는 '리캡(Recap)' 중심으로 루틴을 변경했습니다. Web3나 AI처럼 변화 속도가 빠른 분야에서 일하는 엔지니어에게는 파편화된 지식을 연결하는 이 과정이 필수적입니다.

**2. 활동 지표(Activity)를 통한 리듬 관리**
`claude-agent` 레포지토리의 `commits_7d`가 46에서 48로 증가한 점이 눈에 띕니다. 최근 LLM 에이전트의 실무 적용 가능성을 테스트하며 많은 실험을 진행하고 있는데, 데이터가 이를 증명하고 있습니다. 반면, 유지보수 단계에 들어간 프로젝트들의 활동량은 자연스럽게 줄어드는 것을 확인하며 리소스 배분이 적절히 이루어지고 있음을 체감합니다.

**3. '데이터 기반'의 자기 객관화**
많은 분이 CTO나 시니어 엔지니어는 직관으로 판단한다고 생각하시지만, 사실 가장 강력한 직관은 정교한 데이터 위에서 나옵니다. 제가 씨피랩스에서 기술 전략을 세울 때나 개인 프로젝트를 관리할 때, 이처럼 작은 데이터라도 기록하고 추적하는 습관을 유지하는 이유입니다.

### 마치며

코드 한 줄을 고치는 것보다 더 중요한 것은 **"내가 왜 이 코드를 고쳤는가"**와 **"이 변화가 전체 시스템(혹은 나의 성장)에 어떤 영향을 주는가"**를 파악하는 것입니다.

오늘의 단순한 JSON 업데이트는 저에게 "지난 한 주간 충분히 몰입했는가?"라는 질문에 대한 답을 주었습니다. 여러분도 자신만의 '성장 대시보드'를 만들어보시는 건 어떨까요? 기록이 쌓이면 그것이 곧 실력이 되고, 데이터가 쌓이면 그것이 곧 전략이 됩니다.
