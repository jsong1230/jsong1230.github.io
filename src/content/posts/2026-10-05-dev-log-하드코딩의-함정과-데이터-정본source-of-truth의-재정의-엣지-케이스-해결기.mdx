# [Dev Log] 엣지 케이스의 발견과 데이터 정본(Source of Truth)의 재정의

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey Joo-Han Song)입니다.

개발자에게 가장 짜릿하면서도 괴로운 순간은 "분명히 잘 돌아가고 있었는데, 특정 시점이 되니 갑자기 오작동하는 것"을 발견했을 때가 아닐까 합니다. 오늘 저는 시스템이 '시간'과 '위치'를 해석하는 방식에서 발생한 두 가지 흥미로운 엣지 케이스를 해결했습니다.

### 1. 2026년의 함정: 하드코딩된 연도의 위험성

첫 번째 문제는 날짜 폴더 이름을 실제 `datetime` 객체로 변환하는 `_date_dir_to_date` 함수에서 발생했습니다. 기존 로직은 `MMDD` 형태의 폴더명을 무조건 **2026년**으로 해석하도록 되어 있었습니다.

```python
# 종전 로직: 2026 고정
return datetime.date(2026, mm, dd)
```

운영 초기에는 문제가 없었지만, 2027년으로 넘어가는 시점의 데이터를 처리하려니 요일이 하루씩 어긋나는 현상이 발생했습니다. 2027년 1월 3일(일요일) 폴더를 2026년으로 해석하면 토요일이 되기 때문에, "토요일 확정 시 일요일도 확정"이라는 비즈니스 로직이 꼬여버린 것이죠.

**기술적 결정:**
연도를 고정하는 대신, **'오늘(KST)과 가장 가까운 해'**를 찾도록 로직을 변경했습니다. 오늘을 기준으로 전년, 올해, 내년 세 가지 후보를 생성하고, 그중 오늘 날짜와 차이가 가장 적은 날짜를 선택하는 방식입니다.

```python
# 변경 후: 최근접 occurrence 해석
cands = []
for y in (today.year - 1, today.year, today.year + 1):
    try:
        cands.append(datetime.date(y, mm, dd))
    except ValueError:
        continue  # 2/29 평년 처리
return min(cands, key=lambda d: (abs((d - today).days), d < today))
```

단순히 `+1`을 하는 것이 아니라 `min` 함수와 `abs`를 이용해 유연하게 대응하게 함으로써, 연말연시의 경계선에서도 시스템이 안정적으로 동작하도록 개선했습니다.

### 2. 정본(Source of Truth)의 재정의: Local vs S3

두 번째는 데이터 정합성 검증 스크립트(`verify_news_era.py`)에서 발생한 '오탐' 문제였습니다. AWS 이전 후, 빌더는 S3를 직접 읽어 처리하고 로컬 NVMe 스토리지에는 단순히 사본만 저장하는 구조로 바뀌었습니다. 그런데 검증 스크립트는 여전히 **로컬 파일의 존재 여부**를 정본으로 판단하고 있었습니다.

이로 인해 S3에는 엄연히 존재하지만 로컬 사본이 없는 과거 회차 725편이 전부 `file_missing`으로 처리되는 해프닝이 있었습니다.

**인사이트:**
인프라 구조가 변경되면 **'무엇을 믿을 것인가(Source of Truth)'**에 대한 정의도 함께 바뀌어야 합니다. 저는 검증 우선순위를 다음과 같이 재설계했습니다.

1. **S3에 없는가?** $\rightarrow$ `s3_missing` (치명적: 업로드 누락)
2. **로컬과 S3의 크기가 다른가?** $\rightarrow$ `size_mismatch` (주의: 동기화 오류)
3. **로컬에만 없는가?** $\rightarrow$ **정상** (단, DB의 duration 값이 있는지 확인)

이제 로컬 사본이 없더라도 S3에 파일이 있다면 정상으로 간주하며, 무음 스팟 체크 같은 정밀 검사가 필요할 때만 S3에서 임시로 파일을 내려받아 측정하도록 최적화했습니다.

### 마치며

오늘의 작업은 거대한 아키텍처의 변경은 아니었지만, **하드코딩의 위험성**과 **인프라 변화에 따른 정본 정의의 중요성**을 다시금 일깨워준 시간이었습니다. 

특히 `booksummary` 프로젝트에서는 수능특강(수특) 수록 현대소설이라는 새로운 수요 축을 발견하여 데이터 파이프라인을 확장하는 성과도 있었습니다. 기술적인 디테일을 잡는 것과 비즈니스 기회를 포착하는 것, 이 두 가지의 균형을 맞추는 것이 엔지니어로서 가장 즐거운 지점인 것 같습니다.
