# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적

안녕하세요, 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어로서 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '가시화(Visualization)'입니다. 추상적인 코드의 집합보다, 그 코드가 어떻게 변화하고 어떤 리듬으로 생산되었는지를 보여주는 데이터는 때로 수백 페이지의 문서보다 더 많은 인사이트를 줍니다.

오늘은 제 개인 대시보드의 데이터를 업데이트하며, 최근의 작업 흐름을 복기해 보았습니다. 단순한 `json` 파일의 수정처럼 보이지만, 그 안에는 최근 제가 집중하고 있는 기술적 고민과 씨피랩스에서의 치열한 여정이 고스란히 담겨 있습니다.

### 데이터가 말해주는 집중의 방향

이번 커밋의 핵심은 `dashboard.json`의 업데이트입니다. 특히 흥미로운 부분은 리포지토리별 활동량(activity)의 변화입니다.

```json
// claude-agent 리포지토리의 변화
- "commits_7d": 49,
- "commits_30d": 378
+ "commits_7d": 62,
+ "commits_30d": 404
```

`claude-agent` 리포지토리의 커밋 수가 급증한 것을 볼 수 있습니다. 최근 AI 에이전트의 자율성과 도구 활용 능력을 고도화하는 작업에 몰입하고 있는데, 특히 `docs+tools: Phase 2 closed`라는 메시지에서 알 수 있듯, 씨피랩스의 인프라와 연동되는 툴링 최적화 단계가 마무리 단계에 접어들었음을 의미합니다. 

단순히 기능을 구현하는 것을 넘어, 실제 메인넷 롤링이나 API 업그레이드와 같은 실무 환경(Production)에서의 안정성을 확보하는 과정이 데이터에 그대로 투영되었습니다.

### 기술적 결정과 인사이트: 정적 데이터의 동적 관리

제 대시보드는 정적 사이트 생성기(SSG) 기반으로 동작합니다. 매번 수동으로 데이터를 입력하는 대신, 깃허브 액션(GitHub Actions) 등을 통해 커밋 로그를 분석하고 `dashboard.json`을 자동으로 생성하도록 설계했습니다. 

여기서 제가 내린 기술적 결정은 **'최소한의 상태 유지'**입니다. 복잡한 데이터베이스를 구축하기보다, Git 자체를 Single Source of Truth(SSOT)로 활용하여 JSON 파일 하나에 상태를 기록하는 방식입니다. 이는 Web3의 철학과도 닮아 있습니다. 불필요한 중앙 집중식 저장소 없이, 변경 이력(History) 자체가 곧 데이터가 되는 구조입니다.

### 마치며: 기록은 기억을 이긴다

`heritageradio`나 `booksummary` 같은 개인 프로젝트의 커밋 로그를 보면, 기술적인 작업 외에도 고전 소설을 디지털 콘텐츠화하는 인문학적 시도들이 섞여 있습니다. 블록체인과 AI라는 최첨단 기술의 정점에서 일하지만, 결국 그 기술이 닿아야 할 곳은 인간의 기록과 문화라는 점을 잊지 않으려 노력합니다.

오늘의 작은 `chore` 커밋 하나가 1년 뒤에는 제가 어떤 고민을 하며 성장했는지 보여주는 소중한 이정표가 될 것입니다. 여러분은 오늘 여러분의 성장을 어떻게 기록하고 계신가요?
