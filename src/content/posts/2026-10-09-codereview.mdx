안녕하세요, 시니어 소프트웨어 엔지니어이자 코드 리뷰어입니다.

제시해주신 두 개의 저장소(`gram-jsong`, `booksummary`)의 커밋과 diff를 분석했습니다. 전반적으로 단순한 코드 수정을 넘어, **데이터 기반의 대시보드 관리**와 **AI를 활용한 콘텐츠 제작 파이프라인의 최적화** 과정이 돋보이는 작업입니다.

상세 리뷰를 작성해 드립니다.

---

## ✅ 잘한 점

### 1. 데이터 기반의 철저한 사후 분석 및 기록 (`booksummary/history.md`)
단순히 "영상을 올렸다"가 아니라, **TTS 속도, 렌더링 시간, 파일 크기(md5 대조), 디코드 오류 건수, 수요/경쟁 지수** 등 정량적인 지표를 매우 상세하게 기록하고 있습니다. 특히 `history.md`에 기록된 렌더링 프로세스의 트러블슈팅(ssh pgrep 패턴 문제)은 향후 동일한 실수를 방지하는 훌륭한 기술 문서의 역할을 합니다.

### 2. 반복되는 실패를 통한 프롬프트 전략 수정 (`scripts/gen_flux_gubo.py`)
Flux 이미지 생성 시 1차 시도에서 80%의 높은 폐기율이 발생하자, 이를 단순히 '운'으로 치부하지 않고 **"지명 제거 $\rightarrow$ plain bare walls $\rightarrow$ 클로즈업/뒷모습"**이라는 구체적인 전략 수정(`--set 2`)으로 연결해 성공률을 높인 점이 매우 인상적입니다. 이는 전형적인 엔지니어링적 접근 방식(Hypothesis $\rightarrow$ Test $\rightarrow$ Analysis $\rightarrow$ Optimization)입니다.

### 3. 체계적인 데이터 구조 관리 (`gram-jsong/dashboard.json`)
개인 대시보드 데이터를 JSON 형태로 관리하며 `generated_at` 타임스탬프와 각 레포지토리별 `activity`(7일간의 일일 커밋 수 추정)를 배열로 관리하고 있습니다. 이를 통해 자신의 생산성 추이를 시각화하려는 구조적 설계가 잘 되어 있습니다.

## 🔧 개선할 점

### 1. JSON 데이터의 수동 업데이트 및 관리 효율성 (`gram-jsong/dashboard.json`)
현재 `dashboard.json`의 변경 사항을 보면 수동으로 값을 수정하거나 단순 스크립트로 덮어쓰는 것으로 보입니다.
*   **개선 제안:** 커밋 수, 최근 메시지, 브랜치 정보 등을 GitHub API를 통해 자동으로 수집하여 JSON을 업데이트하는 **GitHub Action 워크플로우**를 구축하시길 권장합니다. 현재처럼 `chore: Update dashboard data`라는 커밋이 반복되는 것은 자동화의 여지가 매우 큽니다.

### 2. 하드코딩된 설정값의 모듈화 (`scripts/gen_flux_gubo.py`)
새로 추가된 파이썬 스크립트에서 이미지 생성 전략이나 프롬프트 관련 설정들이 스크립트 내부에 텍스트로 포함되어 있을 가능성이 높습니다.
*   **개선 제안:** `--set 2`와 같은 옵션이나 `plain bare walls` 같은 핵심 키워드를 별도의 `config.yaml`이나 `prompts.json`으로 분리하세요. 그래야 나중에 다른 작품(예: 태평천하)을 작업할 때 스크립트 로직은 그대로 두고 설정 파일만 교체하여 재사용할 수 있습니다.

### 3. 파일명 인코딩 및 가독성 문제 (`booksummary/data/notebooklm_urls/...`)
diff를 보면 한글 파일명이 `\354\206\214...`와 같이 이스케이프 처리되어 나타납니다. 이는 Git 설정이나 OS 간 인코딩 차이로 발생합니다.
*   **개선 제안:** `git config --global core.quotepath false` 설정을 통해 한글 파일명이 그대로 보이게 설정하시고, 가급적 파일명에는 영문/숫자/언더바(`_`) 조합을 사용하고 실제 한글 제목은 파일 내부의 메타데이터(YAML front-matter 등)로 관리하는 것이 협업 및 CI/CD 환경에서 훨씬 안전합니다.

## 💡 오늘의 기술 포인트

### 🛠️ "AI 생성물의 품질 제어를 위한 Negative Constraint 전략"
오늘 작업의 핵심은 **Flux AI가 생성하는 '불필요한 텍스트/간판'을 어떻게 제어하느냐**였습니다. 

단순히 "글자를 넣지 마라"는 부정 프롬프트(Negative Prompt)만으로는 한계가 있음을 깨닫고, **"벽을 비워라(plain bare walls)", "뒷모습을 찍어라(back view)", "클로즈업하라"**와 같이 **구도와 환경을 강제함으로써 결과적으로 원치 않는 요소를 제거**하는 전략을 선택했습니다. 이는 생성형 AI를 다루는 엔지니어에게 매우 중요한 '제약 조건 설계(Constraint Design)' 능력입니다.
