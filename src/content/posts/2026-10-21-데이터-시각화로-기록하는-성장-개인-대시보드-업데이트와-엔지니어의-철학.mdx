# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적: 대시보드 업데이트

안녕하세요, 송주한(Jeffrey Joo-Han Song)입니다.

엔지니어로 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '가시화(Visualization)'입니다. 복잡한 분산 시스템의 상태를 모니터링하는 것부터, 개인의 성장 지표를 관리하는 것까지, 눈에 보이지 않는 흐름을 데이터로 바꾸어 시각화했을 때 비로소 우리는 객관적인 인사이트를 얻을 수 있기 때문입니다.

오늘은 제 개인 프로젝트인 `jsong1230.github.io`의 대시보드 데이터를 업데이트했습니다. 단순한 `chore` 작업처럼 보일 수 있지만, 이 데이터가 쌓이는 과정에는 저만의 기술적 철학과 고민이 담겨 있습니다.

### 📊 단순한 업데이트, 그 이상의 의미

이번 커밋의 핵심은 `src/data/dashboard.json` 파일의 갱신입니다. 

```json
- "generated_at": "2026-10-19T23:00:01.394Z",
+ "generated_at": "2026-10-20T23:00:01.514Z",
```

매일 자동으로 생성되는 이 데이터는 제가 현재 어떤 기술 스택에 집중하고 있는지, 그리고 어떤 리포지토리에서 가장 활발한 고민이 일어나고 있는지를 보여주는 '디지털 발자국'입니다. 

특히 이번 diff에서 흥미로운 점은 `claude-agent` 리포지토리의 활동량입니다.
`commits_30d` 수치가 `299`에서 `327`로 증가했고, 최근 7일간의 활동량(`commits_7d`) 역시 꾸준히 상승하고 있습니다. 이는 최근 제가 AI 에이전트의 자율성과 LLM 오케스트레이션 최적화에 깊게 몰입하고 있음을 정량적으로 보여줍니다.

### 🛠️ 기술적 결정: 정적 데이터 기반의 대시보드

많은 분이 실시간 API를 통해 데이터를 가져오는 방식을 선호하시겠지만, 저는 개인 대시보드에 **'정적 JSON 생성'** 방식을 채택했습니다. 여기에는 몇 가지 전략적 이유가 있습니다.

1. **성능과 비용의 최적화**: 매번 GitHub API를 호출하는 대신, 빌드 타임에 데이터를 생성하여 정적 페이지로 서빙함으로써 응답 속도를 극대화하고 API Rate Limit 문제를 원천적으로 차단했습니다.
2. **불변성의 기록**: 특정 시점의 상태를 JSON 파일로 남김으로써, 시간이 흐른 뒤 제가 어떤 리듬으로 개발했는지 히스토리를 추적하기 용이합니다.
3. **단순함의 미학**: 복잡한 백엔드 인프라 없이 GitHub Actions와 정적 호스팅만으로 운영 가능한 구조를 유지하여, 유지보수 비용을 제로에 가깝게 만들었습니다.

### 💡 인사이트: 기록이 만드는 복리 효과

씨피랩스에서 CTO로서 수많은 아키텍처를 설계하고 팀을 리딩하며 느낀 점은, 결국 '작은 기록의 누적'이 거대한 기술적 자산이 된다는 것입니다. 

코드 한 줄, 커밋 메시지 하나가 모여 대시보드의 그래프를 만들고, 그 그래프는 다시 저에게 "지금 이 방향으로 계속 나아가도 좋다" 혹은 "새로운 기술적 자극이 필요하다"라는 신호를 줍니다. 개발자에게 있어 이러한 셀프 피드백 루프(Self-Feedback Loop)를 구축하는 것은 지속 가능한 성장을 위한 필수 장치라고 생각합니다.

오늘의 업데이트는 단순한 숫자 변경이었지만, 저에게는 어제보다 한 걸음 더 나아갔음을 확인하는 소중한 과정이었습니다. 여러분은 자신의 성장을 어떻게 기록하고 계신가요?
