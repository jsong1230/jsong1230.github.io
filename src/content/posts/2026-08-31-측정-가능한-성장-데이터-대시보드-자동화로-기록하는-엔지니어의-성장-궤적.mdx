## [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적: 대시보드 자동화의 가치

안녕하세요, 씨피랩스(CP Labs)의 CTO 송주한입니다.

엔지니어로서 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '측정 가능한 성장'입니다. 단순히 "열심히 했다"는 느낌보다는, 내가 어떤 프로젝트에 얼마만큼의 에너지를 쏟았고, 그것이 어떤 결과물로 이어졌는지를 객관적인 데이터로 확인하는 과정이 성장의 핵심 동력이 되기 때문입니다.

오늘 저는 개인 대시보드의 데이터를 업데이트하며, 제가 운영 중인 여러 프로젝트의 활동 지표를 최신화했습니다. 단순한 `chore` 작업처럼 보일 수 있는 `dashboard.json` 업데이트지만, 그 이면에는 엔지니어로서의 루틴과 자동화에 대한 고민이 담겨 있습니다.

### 데이터가 말해주는 오늘의 인사이트

이번 커밋의 diff를 살펴보면 흥미로운 지점들이 보입니다. 특히 `claude-agent` 레포지토리의 활동량이 눈에 띕니다.

```diff
- "commits_7d": 99,
- "commits_30d": 360
+ "commits_7d": 124,
+ "commits_30d": 382
```

최근 7일간의 커밋 수가 99회에서 124회로 급증했습니다. 이는 제가 최근 AI 에이전트의 최적화와 워크플로우 자동화에 깊게 몰입하고 있음을 정량적으로 보여줍니다. 특히 `docs(ops): update handoff note`와 같은 메시지에서 알 수 있듯, 단순한 코드 작성을 넘어 AI와의 협업 과정에서 '상태 관리(State Management)'와 '핸드오프(Handoff)'를 얼마나 정교하게 설계하느냐가 전체 생산성을 결정짓는다는 점을 다시 한번 체감했습니다.

### 기술적 결정: 왜 정적 JSON 데이터인가?

많은 분이 이런 데이터를 관리할 때 DB를 구축하거나 복잡한 API를 생각하시겠지만, 저는 의도적으로 정적 JSON 파일을 통한 업데이트 방식을 유지하고 있습니다.

1. **단순함의 미학**: 개인 대시보드는 복잡한 쿼리가 필요 없습니다. Git 자체가 훌륭한 버전 관리 시스템이자 DB 역할을 하므로, JSON 파일의 변경 이력만으로도 시간에 따른 활동 변화를 추적할 수 있습니다.
2. **배포 최적화**: `jsong1230.github.io`와 같은 정적 사이트 환경에서는 빌드 타임에 데이터를 주입하는 것이 런타임에 API를 호출하는 것보다 훨씬 빠르고 안정적입니다.
3. **자동화 파이프라인**: 이 데이터는 수동으로 입력하는 것이 아니라, 깃허브 API를 통해 활동량을 수집하고 JSON으로 생성하는 자동화 스크립트에 의해 업데이트됩니다.

### 마치며: 기록은 기억을 이긴다

씨피랩스에서 수많은 팀원을 리딩하고 복잡한 아키텍처를 설계하며 깨달은 점은, 결국 '기록하는 습관'이 엔지니어의 가장 강력한 무기가 된다는 것입니다. 

오늘 업데이트한 `dashboard.json`은 단순한 숫자의 나열이 아닙니다. 제가 어떤 고민을 했고, 어디에 시간을 투자했는지를 보여주는 '디지털 발자취'입니다. 여러분도 자신만의 성장 지표를 만들어보시는 건 어떨까요? 정교한 툴이 아니더라도 좋습니다. 기록이 쌓여 데이터가 되고, 그 데이터가 통찰이 되는 경험을 꼭 해보시길 바랍니다.

내일은 또 어떤 데이터가 저의 성장을 증명해줄지 기대하며, 오늘의 로그를 마칩니다.
