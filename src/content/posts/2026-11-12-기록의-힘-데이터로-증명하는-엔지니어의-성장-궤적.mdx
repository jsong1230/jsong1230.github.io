# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어로 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 '기록'입니다. 단순히 코드를 짜는 것을 넘어, 내가 어떤 고민을 했고 어떤 리듬으로 작업했는지를 데이터로 남기는 것은 훗날 아주 소중한 자산이 됩니다.

오늘은 제 개인 대시보드(`jsong1230.github.io`)의 데이터를 업데이트하는 작업을 진행했습니다. 겉보기에는 단순한 JSON 파일 수정처럼 보일 수 있지만, 이 과정 속에는 제가 지향하는 '엔지니어링 라이프사이클'에 대한 고민이 담겨 있습니다.

### 데이터로 보는 최근의 몰입

이번 커밋에서 가장 눈에 띄는 부분은 `metadium-explorer-stack`과 `claude-agent` 리포지토리의 활동량 변화입니다.

```json
// metadium-explorer-stack 변경 사항
"activity": [0, 0, 0, 1, 1, 7, 0],
"commits_7d": 9,
"commits_30d": 28
```

최근 메타디움 익스플로러 스택 작업에서 커밋 수가 급증한 것을 볼 수 있습니다. 특히 서브모듈을 최신 머지본으로 업데이트하는 `chore: 서브모듈을 backend PR #61 머지본으로` 작업과 같은 세밀한 관리 작업들이 이어졌습니다. 블록체인 인프라와 같은 복잡한 스택을 다룰 때는 이처럼 의존성을 명확히 관리하고 버전 간의 정렬(Alignment)을 맞추는 작업이 전체 시스템의 안정성을 결정짓습니다.

또한, `claude-agent` 리포지토리의 활동량은 여전히 압도적입니다. AI 에이전트를 활용한 자동화와 메인넷 상태 체크 로그 등을 지속적으로 업데이트하며, AI와 Web3의 결합 지점을 끊임없이 실험하고 있습니다.

### 기술적 결정: 정적 데이터의 자동화

저는 대시보드 데이터를 수동으로 입력하지 않습니다. `Auto-generate daily posts`라는 메시지에서 알 수 있듯, 깃허브 API와 스크립트를 통해 제 활동 로그를 자동으로 수집하고 JSON으로 변환하여 배포하는 파이프라인을 구축해 두었습니다.

이런 방식의 '자기 기록 자동화'는 두 가지 이점이 있습니다.
1. **객관성**: 주관적인 기억이 아니라, 실제 커밋 로그라는 '팩트'에 기반한 활동량을 측정할 수 있습니다.
2. **효율성**: 기록을 위한 기록에 시간을 쓰지 않고, 오직 개발에만 집중한 뒤 결과물만 데이터로 남깁니다.

### 인사이트: 리듬(Rhythm)의 중요성

`activity` 배열에 담긴 숫자들을 보면 제가 일주일 동안 어떤 리듬으로 움직였는지 보입니다. 어떤 날은 폭발적으로 코드를 작성하고, 어떤 날은 정적인 분석과 설계에 시간을 씁니다.

많은 주니어 엔지니어들이 '매일 일정한 양의 커밋'을 해야 한다는 강박을 갖곤 합니다. 하지만 20년의 경험으로 비추어 볼 때, 중요한 것은 **'지속 가능한 리듬'**입니다. 몰입이 필요한 시점에는 깊게 파고들고, 정리할 때는 차분하게 마무리하는 완급 조절이 장기적인 생산성을 유지하는 비결입니다.

오늘의 데이터 업데이트는 단순한 숫자 변경이 아니라, 제가 설정한 목표를 향해 제대로 나아가고 있는지 확인하는 '체크포인트'와 같습니다. 내일은 또 어떤 데이터가 저의 성장 궤적을 그려낼지 기대됩니다.
