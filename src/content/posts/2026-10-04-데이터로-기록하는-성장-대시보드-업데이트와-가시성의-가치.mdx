# [Dev Log] 데이터의 흐름으로 기록하는 나의 성장 궤적: 대시보드 업데이트와 자동화의 가치

안녕하세요, 씨피랩스의 CTO 송주한(Jeffrey)입니다.

엔지니어로서 20년 넘게 커리어를 쌓아오며 제가 가장 중요하게 생각하는 것 중 하나는 **'가시성(Visibility)'**입니다. 시스템의 상태를 모니터링하는 것뿐만 아니라, 내가 어떤 방향으로 시간을 쓰고 있고, 어떤 기술적 고민을 하며 성장하고 있는지를 데이터로 확인하는 과정은 매우 중요합니다.

오늘은 제 개인 프로젝트인 `jsong1230.github.io`의 대시보드 데이터를 업데이트하며, 기록의 자동화와 그 데이터가 주는 인사이트에 대해 짧게 공유해보려 합니다.

### 🛠️ 오늘의 작업: 대시보드 데이터 동기화

오늘 진행한 작업은 단순해 보이지만, 저의 개발 활동을 정량적으로 추적하는 `dashboard.json` 파일을 업데이트하는 것이었습니다. 

```json
// src/data/dashboard.json 변경 부분
- "generated_at": "2026-10-02T23:00:01.651Z",
+ "generated_at": "2026-10-03T23:00:01.955Z",
```

단순한 날짜 변경처럼 보이지만, 이 JSON 파일은 제가 운영하는 여러 리포지토리의 커밋 횟수, 최근 메시지, 활동성(Activity)을 집계하여 시각화하는 소스 데이터가 됩니다.

### 🔍 데이터에서 발견한 인사이트

이번 업데이트 내역을 살펴보면 최근 제가 집중하고 있는 관심사가 명확히 드러납니다.

1. **보안과 권한 제어의 세밀화**: `heritageradio` 리포지토리의 커밋 메시지 중 `"[admin] fix(audio): /audio/voice_refs/* 는 어드민 토큰이 있어야 서빙"`이라는 부분이 눈에 띕니다. 단순한 기능 구현을 넘어, API 엔드포인트 하나하나에 적절한 권한 제어를 적용하는 것은 Web3나 DID 같은 보안 민감 분야를 다루는 엔지니어에게 습관화되어야 할 기본기입니다.
2. **실험적 접근의 지속**: `booksummary` 프로젝트에서 `"feat: 제목 「줄거리」 실험 시작 — 처치 3편·대조 4편"`이라는 메시지가 보입니다. 기술 개발뿐만 아니라 콘텐츠 생성 과정에서도 A/B 테스트와 같은 실험적 접근을 시도하고 있음을 알 수 있습니다.
3. **자동화의 효율성**: `jsong1230.github.io`의 `"Auto-generate weekly book post"` 메시지처럼, 반복되는 기록 작업은 최대한 자동화하여 '생각하는 시간'을 확보하는 것이 CTO로서 제가 지향하는 생산성 모델입니다.

### 💡 마치며: 기록은 기억을 이긴다

많은 개발자가 코드를 짜는 것에만 집중하지만, 사실 **'내가 무엇을 했는가'를 데이터로 남기는 것**은 추후 기술적 의사결정의 근거가 됩니다. 씨피랩스에서 수많은 프로젝트를 리딩하며 느낀 점은, 잘 정리된 로그와 데이터가 팀의 커뮤니케이션 비용을 획기적으로 줄여준다는 것입니다.

개인 대시보드 역시 마찬가지입니다. 매일 업데이트되는 `commits_7d`와 `commits_30d` 수치를 보며 제가 어느 시점에 슬럼프를 겪었는지, 혹은 어떤 주제에 꽂혀 몰입했는지를 복기합니다.

여러분도 자신만의 '성장 대시보드'를 만들어보시는 건 어떨까요? 거창하지 않아도 좋습니다. 작은 기록의 자동화가 결국 큰 인사이트로 돌아올 것입니다.
